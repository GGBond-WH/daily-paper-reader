## 摘要
Transformer的深度并未被均匀使用：较低层和中间层构建语义表示，而较高层则越来越多地针对预测进行专门化处理。我们将这种分工转化为CoMem（理解记忆），它仅通过一个中间层写入每个上下文块，检索固定数量的缓存残差状态，并在生成的打包结果上重新计算查询条件下的上层。对于固定的检索预算，模型侧的读取计算和内存与存储的上下文长度无关。我们在统一的、无聊天模板的协议下评估了一个持续训练的Qwen3-8B基础语言模型。骨干网络被冻结；主模型仅在普通PG19上训练秩为32的自蒸馏LoRA，并单独报告一个无需适配器的分支。CoMem在RULER上达到97.05，在LoCoMo上达到38.27，而全上下文KV-Direct为34.59；对话记忆优势在对话聚类重采样和独立评估器下依然保持。在额外长上下文和长文档任务上的结果既展示了有界检索的优势，也展示了其在窗口内的压缩代价。受控深度扫描显示，更深的缓存降低了每次查询的重计算，但引入了保真度损失，而自蒸馏可大幅修复这一损失。在NVIDIA H20上128k的独立无适配器效率控制中，CoMem使用18.26 GB而非89.36 GB，并实现了7.83倍的预填充加速。这些结果表明，长上下文记忆可以沿着层轴而非仅沿着token轴进行组织。

## Abstract
Transformer depth is not used uniformly: lower and middle layers build semantic representations, while upper layers increasingly specialize them for prediction. We turn this division of labor into CoMem (Comprehension Memory), which writes each context chunk only through an intermediate layer, retrieves a fixed number of cached residual states, and recomputes the query-conditioned upper layers over the resulting pack. For a fixed retrieval budget, model-side read compute and memory are independent of stored-context length. We evaluate a continued-trained Qwen3-8B base LM under a unified chat-template-free protocol. The backbone is frozen; the flagship trains only a rank-32 self-distillation LoRA on plain PG19, and we report an adapter-free arm separately. CoMem reaches 97.05 on RULER and 38.27 on LoCoMo versus 34.59 for full-context KV-Direct; the dialogue-memory advantage survives conversation-cluster resampling and an independent judge. Results on additional long-context and long-document tasks expose both the benefits of bounded retrieval and its in-window compression tax. Controlled depth sweeps show that deeper caching lowers per-query recomputation but incurs a fidelity loss that self-distillation substantially repairs. In a separate adapter-free efficiency control on an NVIDIA H20 at 128k, CoMem uses 18.26 GB rather than 89.36 GB and achieves a 7.83x prefill speedup. These results show that long-context memory can be organized along the layer axis, not only the token axis.

## 1. 核心问题与整体含义（研究动机与背景）

- **核心观察**：Transformer各层并非同质。现有研究表明，**较低层和中间层构建可使用的语义信息**，而**较高层则逐渐将表征特化为对当前查询和预测的专用化处理**（即"深度分工"）。
- **背景痛点**：长上下文语言建模面临两大瓶颈：
  - 自注意力带来的**二次方预填充（prefill）成本**；
  - 键值（KV）缓存带来的**随上下文长度线性增长的内存开销**。
  - 此外，模型还有原生位置窗口限制（Qwen3-8B为40,960 token）。
- **现有方案的不足**：
  - 多数方法沿 **token 轴** 进行压缩/淘汰/检索（如 StreamingLLM、H2O、SnapKV、InfLLM 等）；
  - 最近的 HCache 虽缓存中间层激活并重算上层，但缺乏检索机制；KV-Direct 虽证明 KV 可从残差流重建，但保留全部 token，工作集仍随上下文增长。
- **核心洞见**：既然深层状态是"查询条件化"的，缓存一个**查询无关的中间残差状态**，在读取时用查询重算上层，就能同时做到：
  - 存储只随上下文长度**线性增长**；
  - 模型侧在线读取的计算与内存**与存储的上下文长度无关**（有界）。
- **整体含义**：长上下文记忆不仅可以沿 token 轴组织，还可以沿 **layer 轴（深度轴）** 组织，这是一个互补的新维度。

## 2. 方法论：CoMem（Comprehension Memory）

### 2.1 核心思想

将 Transformer 沿深度分成两部分：
- **下层 [0:j]**：负责建立语义，写入阶段只需运行这一部分；
- **上层 [j:L]**：负责查询条件化的预测，读取阶段才有必要运行。

### 2.2 算法流程（Write / Select / Read）

**Write（写入阶段）** ：
- 将文档切分为不重叠的 **512-token 块**；
- 每个块从位置 0 重新开始 RoPE，仅通过层 [0:j]（旗舰版 j=12/36）；
- 将每 token 的残差张量 hj 存入外部存储（按文本建立索引）。

**Select（检索阶段）** ：
- 使用**迭代式 BM25** 检索 top-k 相关块（旗舰版 k=12，hop width=4，自动三轮前沿扩展）；
- 检索是有界的，与存储上下文总长度无关。

**Read（读取阶段）** ：
- 将 [BOS；选中的 hj；查询的 hj] 打包成一个序列，使用**全新的连续 RoPE**；
- 仅对层 [j:L] 进行完整因果注意力的重计算；
- 最终读取 token 数 ≈ sink + k×c + query ≈ **6.7k token**，与存储上下文长度**无关**。

### 2.3 存储效率公式

每个 token 的缓存存储量与完整 KV 之比：

|hj| / |KV| = d / (2L·dkv) = nq / (2L·nkv)

对于 Qwen3-8B：d=4096, L=36, nq=32, nkv=8 → 比例为 **1/18**（每 token 8 KB vs 144 KB，bf16）。

### 2.4 自蒸馏（Self-Distillation）

- 训练一个 **秩-32 LoRA**（α=64，零 dropout）作用于层 12–35 的所有 attention 和 MLP 投影；
- 以冻结的 j=0 教师模型在 top-64 logit 支持上的输出为目标；
- 损失：**双向 KL 散度**：L = 0.6·KL(p∥q) + 0.4·KL(q∥p)，无辅助 CE 项；
- 训练数据仅为 **PG-19 纯文本**，无检索、无任务监督、无合成长上下文示例；
- 目的：将"可读深度"（zero-shot readable depth）推得更深，修复深层缓存状态的读出保真度。

## 6. 主要结论与发现

1. **深度分工是真实且可资利用的**：低/中层建立语义，深层特化预测；这一分工可用于设计高效记忆系统。
2. **缓存中间残差 + 重算上层是可行的**：每 token 仅需完整 KV 的 1/18 存储，读取端计算与内存与存储上下文长度无关。
3. **有界检索优于全量上下文**：在 128k 内，CoMem 在 RULER 上保持 95+ 的变量追踪准确率，而同预算的 StreamingLLM 跌至 0.8。
4. **自蒸馏能有效修复深层缓存的可读性**：PG-19 纯文本训练的 LoRA 在同一 split j=12 下恢复 13.75 个 LoCoMo 点，证明是"接口适配"而非任务特定训练。
5. **深度是质量-成本旋钮，而非免费午餐**：更深的 split 降低查询成本但损失冻结读出保真度。
6. **长上下文记忆可沿层轴组织**：这是对传统"仅沿 token 轴优化"的重要补充视角。

## 7. 优点与亮点

1. **视角新颖**：将"深度分工"这一可解释性观察转化为实际的记忆系统设计，是"理解→工程"的直接范例。
2. **读取复杂度与上下文解耦**：不依赖 token 压缩或淘汰，而是通过"有界检索 + 有界重算"实现真正的常数级读取。
3. **机制消融设计严谨**：
   - j=0 控制隔离"检索增益"与"深度复用增益"；
   - 同 j 的 LoRA 开关隔离"适配增益"；
   - 块对角注意力控制隔离"跨块交互"价值。
4. **自蒸馏设计轻量优雅**：
   - 冻结骨干，仅训练秩-32 LoRA；
   - 仅用 PG-19 纯文本，无任何任务监督；
   - 训练仅约 3 H20 GPU-hours，成本极低。
5. **统计验证超越常见水平**：不仅报告点估计，还做了 item bootstrap、cluster bootstrap、独立 judge 审计和跨尺度趋势分析。
6. **泛化验证扎实**：跨 6 个模型尺度、两个稀疏 MoE 架构（含 80 层 Hy3）验证方法通用性。
7. **坦率的边界说明**：论文清晰地界定了 40,960 token 以上为"未扩展应力参考"而非长扩展上界，不夸大适用范围。

## 8. 不足与局限

### 8.1 实验覆盖局限

- **仅英文**，且偏重检索式 QA，未覆盖长文本生成、代码、多语言或多模态记忆；
- **BABILong qa2 仍弱**（27.0），窗口内压缩代价明显，全上下文（KV-Direct）在窗口内仍是强参考；
- LoCoMo 仅 10 个对话簇，代表性有限；
- 合成单元 n=100，部分消融无多随机种子或配对检验。

### 8.2 方法局限

- **BM25 词法检索**在相关段落与查询表面形式差异大时可能失效；未测学习型/稠密检索器；
- **动态更新/删除**（持续变化的记忆流）不在当前范围内；
- 检索宽度是**任务相关的**超参数（约 17k 的扩展读取反而变差）；
- 自然多跳工作负载的**检索延迟未测量**。

### 8.3 效率测量局限

- 效率测量为**单查询 harness**，未覆盖批处理、并发服务、存储 I/O 和网络化外部存储；
- 索引构建能耗与持久存储总容量未测量；
- Write 成本需多查询摊还，单次短查询时预处理可能不划算。

### 8.4 偏差风险

- GPT-4o 端点**无固定日期快照**；
- 部分较长上下文结果可能受生成 token 预算不足的影响（如 14B 无聊天模板的长思维链）；
- 未测量训练总 GPU 时长（含失败实验）。

### 8.5 应用限制

- 需要对外部记忆存储实施**访问控制**和敏感内容过滤/删除机制；
- 不是安全性机制本身，继承幻觉、偏见、不安全补全等风险。
