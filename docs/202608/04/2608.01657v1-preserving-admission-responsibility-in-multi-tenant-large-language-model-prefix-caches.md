## 摘要
共享前缀缓存将图形处理单元（GPU）内存转化为跨大型语言模型（LLM）租户共享的持久状态。一个物化新键值（KV）块组可能迫使另一个组丢失可重用状态，然而请求时调度器只考虑瞬态服务，替换策略主要对对象价值排序，而静态分区则使空闲容量闲置。我们将这种不匹配称为准入责任鸿沟。为了弥合这一鸿沟，我们提出了PrefixShield，它对新增物化的完整KV块进行计量，在请求间传递责任，在债务未清时阻止复用提升，并利用预期债务选择提供逐出候选的组。我们在vLLM中实现了PrefixShield。在一次性污染下的配对运行中，PrefixShield相比最近最少使用（LRU）策略将受害者缓存命中率提高了9.39个百分点，相比S3-FIFO提高了8.64个百分点，在4096块规模下将受害者命中率从4.92%恢复至84.87%，并且在两遍重放下相比S3-FIFO获得2.00个百分点的提升。它保留了良性的ShareGPT行为和对空闲容量的工作守恒访问。延迟重放在债务未清时产生35.16个百分点的优势。这些结果表明，对象价值信号对保留内容进行排序，而持久责任决定了哪个组承受回收压力。

## Abstract
Shared prefix caching turns Graphics Processing Unit (GPU) memory into persistent state shared across Large Language Model (LLM) tenants. A group that materializes new Key-Value (KV) blocks can force another to lose reusable state, yet request-time schedulers account for transient service, replacement policies primarily rank object value, and static partitioning strands idle capacity. We call this mismatch the admission-responsibility gap. To close it, we propose PrefixShield, which meters newly materialized full KV blocks, carries responsibility across requests, gates reuse promotion while debt remains, and uses projected debt to select the group supplying eviction candidates. We implement PrefixShield in vLLM. In paired runs under one-touch pollution, PrefixShield improves victim cache hit ratio by 9.39 percentage points over the Least Recently Used (LRU) policy and 8.64 points over S3-FIFO, restoring the victim from 4.92% to 84.87% at 4096-block scale, and gains 2.00 points over S3-FIFO under two-pass replay. It preserves benign ShareGPT behavior and work-conserving access to idle capacity. Delayed replay yields a 35.16-point advantage while debt remains. These results show that object-value signals rank what to retain, while persistent responsibility determines which group bears reclamation pressure.

# 论文详细总结

## 1. 核心问题与整体含义

- 多租户 LLM 共享前缀缓存将 GPU 内存变成跨租户的**持久共享状态**：一个租户物化新的 KV 块，可能迫使另一租户丢失可复用的缓存状态。
- 现有机制存在“准入责任鸿沟”：
  - 请求时调度器只核算瞬时计算资源，不追踪请求结束后仍存留的缓存压力；
  - 替换策略（如 LRU、S3-FIFO）只按对象局部价值排序，不识别“是谁制造了需要逐出的压力”；
  - 静态分区虽能隔离，但会使空闲容量无法被借用，损失工作守恒。
- 核心含义：需要一个**既保持全局共享与工作守恒，又能让制造缓存压力的租户承担后续回收责任**的机制。

## 2. 方法论：PrefixShield

### 核心思想

写入新 KV 块会形成持久压力，责任应随状态保留，直到对应“准入债务”偿还。债务未清时，不能通过重放复用“洗白”成高保留状态；当容量争用时，用债务选择“哪个组承担逐出”，再用保留分类选择“该组中哪个块被逐出”。

### 关键技术细节

- **全量计量**：只对请求中“新物化的完整 KV 块”计数，纯缓存命中不产生新费用（请求长度相似时，新块数可能差异很大）。
- **每租户/每服务合同的令牌桶**：
  - 余额 \(B_{g,c}(t)\)，补充速率 \(\rho_c\)，突发容量 \(\beta_c\)；
  - 惰性补充公式：\(B_{g,c}(t)=\min\{\beta_c,\;B_{g,c}(t_0)+\rho_c(t-t_0)\}\)；
  - 新块产生时扣减：\(B_{g,c}(t)=B_{g,c}(t)-\text{nr}\)；
  - 原始债务 \(D_g(t)=\sum_c \max\{0,-B_{g,c}(t)\}\)。
- **债务门控复用提升**：块被重新访问时，只有“证明复用 + 同一组/合同/前缀 + 组级债务已清空”才能升级到 REUSE 类；否则只记录访问证据，停在当前保留类。
- **两阶段逐出**：
  - 用归一化债务 \(\tilde D_g(t)=\sum_c \max\{0,-B_{g,c}(t)\}/w_c\)（\(w_c=\rho_c/\rho_{\min}\)）选择责任组；
  - 在组内按 `PROBATIONARY ≺ NORMAL ≺ REUSE` 顺序选择逐出块。
- **工作守恒**：债务不是占用上限，也不拒绝准入；空闲时任何组可自由使用真实空闲块，只有在容量争用时责任才生效。
- 两个不变量：
  - I1（完整压力归因）：每个新物化块恰好被归属到引入它的组；
  - I2（无债务洗钱）：复用证据在债务未清时不能立即将块提升为 REUSE。
- 算法流程：请求侧计量新块并设置初始类 → 触摸时记录复用并执行债务门控提升 → 回收时先取真实空闲块，再按投影债务选组、按保留类选块。

## 3. 实验设计

### 平台与实现

- 基于 **vLLM 0.10.2 V1 前缀缓存路径**实现，不修改模型权重、注意力内核或 KV 张量内容。
- 默认平台：**NVIDIA L4 + Qwen2.5-1.5B-Instruct**；可移植性测试使用 A100 及 Qwen2.5-7B。

### 基准配置

- 默认 512 个 GPU KV 缓存块（511 可用），块大小 16 token，共享前缀 1536 token，名义负载 60%。
- PrefixShield 固定策略参数（三种服务合同的补充速率/突发容量），不对每个轨迹重调。

### 对比方法

- **LRU**：vLLM 全局工作守恒替换。
- **S3-FIFO**：工作守恒的快速降级重用感知策略，无租户/责任元数据。
- **StaticQuota**：等量静态分区，代表硬隔离。

### 工作负载

- 攻击轨迹：
  - **One-touch**：不断引入未见前缀（一次性污染）；
  - **Low-and-slow**：随时间低速率散布类似压力；
  - **Two-pass replay**：重放已准入前缀，模拟“复用洗白”。
- 良性轨迹：**ShareGPT** 与 **Bursty ShareGPT**。
- 工作守恒：**Controlled borrowing**（一个组空闲，另一组可借用多少容量）。
- 所有攻击轨迹使用 4 个 1536-token 受害者热前缀，约 384 块（默认规模下占可用块的 75%）。

- 主要实验覆盖 6 个工作负载（3 个攻击 + 2 个良性 + 1 个借用场景）。
- 敏感性实验：
  - 缓存容量 512/1024/2048/4096（8 倍范围）；
  - 创建压力比 λ_new/ρ（0.54–4.23）；
  - 名义负载 40%/60%/80%；
  - 硬件 L4 vs A100；
  - 模型 1.5B vs 7B。
- 消融实验：
  - 无“复用分段逐出”的对比（One-touch、Low-and-slow、ShareGPT、Borrowing）；

- 统计方式：10 次配对运行，报告 95% bootstrap CI。
- 总体评估：
  - **充分**：覆盖直接污染、低慢旋转、重放、良性、借用、容量伸缩、负载变化、部署变化与两个关键机制消融；
  - **客观**：与 LRU（全局）、S3-FIFO（对象价值）、StaticQuota（硬隔离）三类代表基线比较，配对轨迹一致；

## 6. 主要结论与发现

- **One-touch 污染**：受害者命中率从 LRU 的 5.54% 提升到 PrefixShield 的 14.93%（+9.39 pp，95% CI 7.94–10.96）；比 S3-FIFO 高 8.64 pp（95% CI 7.23–9.43）。
- **4096 块规模**：LRU 受害者命中率 4.92%，PrefixShield 恢复至 84.87%，提升 79.95 pp，说明容量越大保护收益越显著。
- **Low-and-slow**：PrefixShield 将攻击下的受害者命中率恢复到 98.90%（+6.26 pp，恢复 95.5% 的平均损失），比 S3-FIFO 高 0.25 pp（95% CI 0.06–0.51）。
- **Two-pass replay**：PrefixShield 受害者命中率 95.97%，比 S3-FIFO 高 2.00 pp（95% CI 0.93–3.23），且 P95 TTFT 更低（104.8 ms vs 141.3 ms）。
- **良性场景**：ShareGPT 上命中率 38.92% vs S3-FIFO 38.85%，统计不可区分；Bursty ShareGPT 上 38.10% vs 38.72%，同样无显著差异，说明无需牺牲良性行为。
- **工作守恒**：PrefixShield 与 S3-FIFO 都能借用 509–510/511 块；PrefixShield 命中率与 LRU 同为 99.33%，静态配额只有 254–255 块，命中率 18.18%。
- **延迟重放消融**：债务未清时 PrefixShield 优势达到 35.16 pp；债务清空后无门控变体与完整版收敛。
- **开销**：默认 512 块/8 组下逐出选择 P95 0.511 ms，吞吐基本无差（5.956 vs 5.955 req/s）。
- 总体：**对象价值信号决定“保留什么”，持久责任决定“由哪个组承受回收压力”**。

## 7. 优点

- 问题定义清晰，识别了现有缓存系统未解决的多租户持久责任缺失。
- 设计上将“创建责任”“复用价值”“物理争用”三个信号分离，机制简洁且可组合。
- 不采用硬分区或准入拒绝，保持全局共享和工作守恒，符合云服务实际需求。
- 责任是暂时性的：停止超额创建后债务随补充速率清零，不会永久惩罚租户。
- 在 vLLM 上实现侵入性低，不修改模型计算与 KV 内容。
- 理论上有“静默债务清除”命题，保证门控不会永久失效。
- 实验范围较广，含 8 倍容量、负载、硬件、模型的跨部署验证，以及两个针对性消融，配对 CI 增强了结果可信度。

## 8. 不足与局限

- **跨组内容去重**：原生前缀查找按租户命名空间隔离，跨组内容复用时所有权与责任归属规则未定义，论文明确将其列为未来工作。
- **实现扩展性**：原型采用软件扫描候选块；4096 块/32 组时 P95 升至 3.149 ms，论文仅提出“可用索引队列优化”，未实现验证。
- **元数据占用**：Python 原型在 4096 块/32 组时约 1.57 MiB，含 Python 对象开销，可能不代表生产级实现。
- **场景覆盖**：使用合成轨迹而非真实生产多租户轨迹；默认配置中受害者热集占可用块比例过高，虽然有利于产生可控争用，但与真实部署场景可能有距离。
- **静态配额基线**：StaticQuota 使用等量分区，其受害者分区（255 块）小于热集（384 块），导致命中率极低；这虽然是公平比较的一种选择，但并不能完全代表最优硬隔离配置。
- **威胁模型边界**：明确排除无限创建新会计组、内存安全攻击、网络泛洪等场景，实际环境中的责任规避可能更复杂。
- **未与同类责任感知系统比较**：因为该问题是首次提出，所以只对比了通用替换策略，缺少同类方法对照。
