## 摘要
前缀键值（KV）复用避免了大型语言模型（LLM）推理中的重复预填充，但本地未命中需要重新计算或副本获取。它们的相对成本因硬件、前缀深度、KV有效吞吐量和副本位置而异，这使得基于命中率的放置方案变得次优。为解决此问题，我们提出了一种周期级规划器PrefixPlace，它在内存预算和需求、计算及传输成本画像下分配前缀完整目标。目标分解为本地副本价值加上首副本覆盖，源相关成本产生单调设施选址目标；每次工作节点更新是一个加法有根树问题，对于n个块和容量k可在O(nk)时间内精确求解，得到固定顺序的1/2近似，坐标细化和顺序多样起点可进一步提升而不削弱保证。T4、L4和A100的测量揭示了不同场景。在432个具有精确最优解的实例中，PrefixPlace平均达到最优解的99.84%，且不低于98.02%。在检索增强生成（RAG）重放中，它相比vLLM自动前缀缓存（vLLM-APC）提高了40.3%的物化成本节省，相比最佳离线基线提高了6.3%。在WikiQA上，提升分别为40.4%和5.3%。最后，PrefixPlace在单处理器上于12.3秒内解决了50000节点、16工作节点的放置问题，支持及时重新规划。

## Abstract
Prefix Key-Value (KV) reuse avoids repeated prefill in Large Language Model (LLM) inference, but local misses require recomputation or replica fetches. Their relative cost varies with hardware, prefix depth, KV goodput, and replica location, making hit-rate-based placement suboptimal. To address this issue, we propose an epoch-level planner, PrefixPlace, which assigns prefix-complete targets under memory budgets and profiled demand, compute, and transfer costs. The objective decomposes into local-copy value plus first-replica coverage, and source-dependent costs yield a monotone facility-location objective; each worker update is an additive rooted-tree problem solved exactly in O(nk) time for n chunks and capacity k, giving a fixed-order 1/2-approximation that coordinate refinement and order-diverse starts improve without weakening. T4, L4, and A100 measurements reveal distinct regimes. Across 432 instances with exact optima, PrefixPlace averages 99.84% of optimum and never falls below 98.02%. In Retrieval-Augmented Generation (RAG) replays, it improves materialization-cost saving by 40.3% over vLLM Automatic Prefix Caching (vLLM-APC) and 6.3% over the best offline baseline. On WikiQA, gains are 40.4% and 5.3%. Finally, PrefixPlace solves a 50,000-node, 16-worker placement in 12.3 s on one processor, enabling timely replanning.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：在 LLM 服务中，前缀 KV（Key-Value）缓存复用可以避免重复的前缀预填充（prefill）计算，是提升吞吐、降低延迟的关键技术。然而，当某个 worker 本地没有所需前缀时，存在两种恢复手段：**重新计算**（recompute）或从其他持有者**获取副本**（fetch）。
- **核心问题**：这两种恢复方式的相对成本并非固定，而是取决于具体硬件（GPU 型号）、前缀深度、KV 占用大小、有效 KV 传输好put（goodput）、副本所在位置等。因此，传统的**基于命中率（hit-rate）的缓存放置策略是次优的**——同样的逻辑前缀块，在不同硬件上可能分别适合获取或重算，需要一种**成本感知的（cost-aware）协同放置规划**。
- **整体含义**：论文提出将前缀 KV 放置建模为一个**周期级（epoch-level）组合优化问题**，在内存预算、需求矩阵、计算/传输成本画像下，为每个 worker 决定“应保留哪些前缀块”，并给出带理论保证的高效求解算法。这项工作填补了现有本地缓存调度（如 vLLM、SGLang）与 KV 传输/分层存储（如 Mooncake、CacheGen）之间“**放置决策**”的空白。

## 2. 方法论：核心思想、关键技术细节与算法流程

### 2.1 核心建模思想

- **前缀块与 prefix-complete 约束**：将连续引擎块分为“放置块”（placement chunk），每个 worker 的放置目标必须是**前缀闭合的（parent-closed）**——若选中某块，则其所有可缓存祖先也必须选中，以保留完整前缀语义。
- **成本模型**：定义了本地物化成本 \(w_m(b)\)、传输成本 \(f_m(b)\)（源无关）或 \(f_{m\leftarrow h}(b)\)（源相关），允许任意画像而不要求线性深度-成本关系。

### 2.2 关键分解：模块化 + 覆盖价值

- **本地价值**：\(a_m(b) = \Lambda_m(b)\min\{w_m(b), f_m(b)\}\) —— 表示 block \(b\) 存储在 worker \(m\) 本地时，该 worker 获得的基本节省。
- **首副本覆盖价值**：\(\Delta(b) = \sum_m \Lambda_m(b)[w_m(b)-f_m(b)]_+\) —— 表示第一个远程副本带来的共享节省。
- **Lemma 1**：总节省可**精确分解**为本地模块化项加上覆盖项，且目标函数关于 worker-chunk 放置元素是**单调子模的**。这一分解是后续算法的基础。

### 2.3 源相关成本的扩展

- 对于传输成本取决于源的情况，目标函数变为**单调子模的设施选址形式**（式 6）。
- **Proposition 1**：固定其他 worker 的放置后，某个 worker 的精确边际放置问题仍可转化为带加性节点利润的有根树选择问题（式 7），因此与源无关情况共享同一求解内核。

### 2.4 算法流程（PrefixPlace）

- **精确单 worker 有根树 oracle（Rooted DP）**：
  - 对前缀树做先序编号，定义 `next(i)` 跳过子树后的下一个位置；通过动态规划递推 \(D[i,j]=\max\{D[next(i),j], p(b_i)+D[i+1,j-1]\}\)，在 \(O(nk)\) 时间内精确求解预算 \(k\) 下的最优父闭集合。
- **联合放置的困难性与近似**：
  - **Theorem 2**：即使所有 worker 硬件相同、成本仅依赖深度，联合放置问题也是**强 NP 难**的（从 3-Partition 归约）。
  - **WorkerGreedy（Theorem 3）**：按任意固定顺序逐个对 worker 执行精确 DP 优化其各自边际价值，得到 **1/2 近似保证**；该结果对源无关和源相关目标都成立。
- **细化与多起点**：
  - **坐标细化（coordinate refinement）**：逐个移除 worker，基于其他 worker 的当前放置重算边际利润，重新运行精确 DP，仅接受严格更优解，收敛到坐标最优且不破坏 1/2 保证。
  - **顺序多样性（order-diverse starts）**：对 \(M\le5\) 枚举所有 worker 顺序；否则使用 standalone-score 顺序、其逆序和 6 个固定伪随机排列；还加入 Independent、Popularity、LocalDedup 作为候选，保证输出不劣于这些基线。
- **重规划机制**：当需求或路由变化时，比较当前解与新优化解的预测收益，仅当收益覆盖一次性物化成本时才更新放置。

## 6. 主要结论与发现

- **硬件差异导致相反的放置决策**：相同模型与网络条件下，T4 偏向 fetching，L4 存在交叉点，A100 更偏向 recomputation，说明统一的 hit-rate 策略必然次优。
- **近似质量极高**：432 个实例上平均达到最优的 99.84%，最低 98.02%；源相关 45 实例平均 99.62%；LP 上界下平均 99.66%。
- **协调价值显著**：在 RAG 回放中，PrefixPlace 比 vLLM-APC 节省 40.3% 物化成本，比最佳离线基线提高 6.3%；WikiQA 上分别高出 40.4% 和 5.3%。
- **消融实验证实组件贡献**：单次 WorkerGreedy 平均 98.15%，增加坐标细化提升到 98.93%，再增加顺序多样性提升到 99.84%，最终 safeguard 将最小比率从 97.55% 提升到 98.02%。
- **可扩展性好**：5 万节点、16 worker 的放置问题在单 CPU 上 12.3 秒求解；需求漂移后 96.8% 的更新可以在 5,000 个请求内回本。

## 7. 优点

- **理论保证与实用性结合**：给出 1/2 近似（Theorem 3），同时通过细化获得接近 1 的经验最优性（平均 >99%），兼顾可证明性和实际效果。
- **精确高效的 oracle**：O(nk) 单 worker 有根树 DP 是简洁且可复用的核心原语，相比一般的树背包卷积更高效。
- **建模的优雅分解**：用“本地价值 + 首副本覆盖”精确分解目标，可直接解释协调的价值来源，也便于扩展到源相关成本的设施选址形式。
- **不依赖特定成本规律**：接受任意 profiled 成本表，无需假设线性深度-成本或固定硬件特性，适应性更强。
- **考虑了实际工程约束**：prefix-complete 约束、内存预算、兼容性过滤（模型权重、精度、并行布局）、重规划摊销规则，贴近真实系统需求。
- **评估方法严谨**：用精确 MILP 做金标准、LP 上界做更大规模的参考，消融细致，鲁棒性和灵敏度考察全面。

## 8. 不足与局限

- **依赖精确画像与需求矩阵**：方法的有效性建立在准确的 `w(b)`、`f(b)` 和需求 \(\Lambda\) 之上；实际在线系统中这些动态变化很快，画像成本与滞后性可能削弱收益。
- **缺乏真实端到端系统验证**：论文没有在真实多机分布式推理系统（如 vLLM + 网络传输）中进行整体部署测试，也没有考虑实际排队、路由调度、网络拥塞等动态因素。
- **与 vLLM-APC 对比的公平性争议**：vLLM-APC 作为在线 LRU 基线，在离线重放和“冻结缓存”评分下可能处于劣势；且实验中只用了默认 LRU，没有调优或对比其他先进在线策略。
- **精确最优实例规模有限**：432 个实例均只有 175–189 块和 3 个 worker；更大规模的“接近最优”是相对 LP 上界而非精确最优，仍可能存在差距。
- **源相关实验较轻**：45 个实例和特定拓扑（两组内 10 Gb/s、组间 1–3 Gb/s）无法完全覆盖网络异构场景的多样性。
- **评估偏向节省率而非端到端 QPS/延迟**：物化时间节省是代理指标，未直接展示吞吐提升或 P99 延迟改善，可能不足以说明实际服务质量的提高。
- **时间与尺度限制**：仅测试了 Qwen2.5 系列和三种 GPU，未覆盖更多模型架构、量化方式或 AMD/华为等非 NVIDIA 硬件。
