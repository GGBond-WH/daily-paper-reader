## 摘要
LLM代理会积累长轨迹的推理步骤、工具调用和环境反馈，使得KV缓存成为主要的推理瓶颈。KV缓存压缩可以降低这一成本，但大多数现有方法假设静态上下文，即未来查询已知或可离线近似。代理则需要在线压缩：必须在未来相关性已知之前压缩新信息，并使用足够廉价的代理查询以适配推理路径。我们研究了令牌驱逐（TE）和注意力匹配（AM）两种在线压缩方法，将两者适配为压缩代理回合，并比较了边界查询、重复预填充和延迟未来生成查询等廉价代理来源。在BrowseComp-Plus和WideSearch上的实验表明，即时压缩往往损害性能，而延迟压缩以使用代理的未来查询则能弥补大部分差距。此外，在不完美代理下，TE通常比AM更鲁棒。在不同规模的模型中，TE在将KV缓存减少80%的同时保留了大部分准确性，并能相比无压缩基线提升吞吐量。这些结果将代理查询选择定位为实用在线KV压缩的核心设计选择。

## Abstract
LLM agents accumulate long trajectories of reasoning steps, tool calls, and environment feedback, making the KV cache a major inference bottleneck. KV cache compaction can reduce this cost, but most prior methods assume a static context where future queries are known or can be approximated offline. Agents instead require online compaction: new information must be compressed before future relevance is known, using proxy queries cheap enough for the inference path. We study online compaction across token eviction (TE) and attention matching (AM), adapting both to compact agent turns and comparing cheap proxy sources such as boundary, repeat-prefill, and delayed future-generation queries. Experiments on BrowseComp-Plus and WideSearch show that immediate compaction often hurts performance, whereas delaying compaction to use the agent's future queries recovers much of the gap. Moreover, TE is often more robust than AM under imperfect proxies. Across models at different scales, TE preserves most of the accuracy while reducing KV cache by 80%, and can improve throughput over the no compaction baseline. These results position proxy-query selection as a core design choice for practical online KV compaction.

- 论文聚焦 **LLM（大型语言模型）智能体的在线 KV 缓存压缩问题**。在长程智能体任务中，模型反复进行推理、工具调用、环境反馈观察，不断追加新内容到上下文，导致 KV 缓存随轨迹增长而成为推理期间的主要内存与计算瓶颈。
- 传统 KV 压缩方法大多面向**静态上下文**：完整文档或提示词在生成前已知，未来查询可以离线近似或通过额外计算获得，因此压缩时能利用较充分的信号。
- 智能体场景是**在线而非静态的**：新信息必须在未来查询未知时就被压缩；而压缩步骤还会直接进入智能体推理循环，占用推理路径上的时间预算，不能使用过于昂贵的策略。
- 论文因此提出核心研究问题：**在在线压缩条件下，应该用什么信号指导压缩？信号质量与运行时开销如何与压缩方法交互？** 作者将其归纳为“代理查询（proxy queries）选择”这一核心设计变量。
- 整体含义：在线压缩不是简单的注意力近似问题，而是一个需要同时考虑任务性能、代理行为变化和推理效率的系统级设计问题。

## 2. 方法论

- **两类压缩方法**
  - **令牌驱逐（Token Eviction, TE）**：使用代理查询对缓存中各位置计算注意力质量得分，保留得分最高的一组原始 key/value。它是纯选择方法，不修改任何 KV 内容。
  - **注意力匹配（Attention Matching, AM）**：使用与 TE 相同的基于代理查询的 key 选择，但额外拟合两个参数：一个加性注意力偏置和一组被压缩后的 value，使得压缩缓存上的注意力输出尽量接近完整缓存的注意力输出。优化分为两步：先匹配未归一化的注意力质量分布，再最小化注意力输出的 Frobenius 范数误差。
- **在线压缩流程**
  - 将轨迹划分为“回合”：系统提示/用户提问作为不压缩前缀，之后每个回合包含助手生成内容和工具响应。
  - 已完成回合被压缩后冻结，后续生成只读取压缩表示；未被压缩的前缀、仍在延迟窗口内的原始回合继续保留完整 KV。
  - 对混合注意力模型（Qwen3.5、Gemma-4），只压缩 full-attention 层，跳过 GatedDeltaNet、sliding-window 等非标准层，并保留角色边界等结构化 token。
- **代理查询来源**
  - **当前回合代理**：立即压缩时可用，包括：①边界查询，提取真实轨迹中结构结束 token 的 query 向量；②重复预填充查询，通过让模型“重复上一回合内容”获取仅供压缩用的 query 向量。
  - **未来回合代理**：延迟 k 个回合再压缩，使用智能体随后生成过程中实际产生的 query 向量作为代理。延迟越大，代理越接近未来实际读取方式，但缓存节省也越晚实现。
- **压缩比例与预算**：实验默认将每个可压缩段压缩到原始长度的 20%，逐层、逐 KV head 独立处理；不同代理源按固定配额或等长拼接方式组合。

## 6. 主要结论与发现

- **即时压缩往往损害任务性能**；延迟压缩至未来回合查询可用之后，能恢复大部分性能差距。
- **代理查询选择比压缩方法本身更关键**：边界查询在某些场景是强即时信号（尤其在 BrowseComp-Plus 上），但未来回合查询整体上更稳定可靠。
- **合并多个代理源并不稳定带来增益**：在延迟未来查询可用后，额外加入当前回合或工具响应查询基本没有一致提升。
- **TE 比 AM 更鲁棒**：在代理查询不完美、压缩比和延迟变化的多种选择下，TE 始终与更复杂的 AM 竞争性能相当；AM 的额外优化在在线约束下收益有限。
- **更大模型上的效率收益明显**：Qwen3.5-27B 在压缩比 0.2 时将峰值 KV 从约 612.9k 降到约 175k token，可承载 batch 从 8 增至 32，吞吐量提升最高 4.2 倍；Gemma-4-31B 峰值 KV 从约 272.1k 降至约 99.6k–121.3k，吞吐量提升 1.5–1.7 倍，同时准确率基本保持甚至略高。
- **压缩会改变智能体行为

- **压缩会改变智能体行为**：论文对搜索轨迹做了行为层面的诊断，发现压缩后智能体生成检索查询的最近邻相似度和重复率均有所上升。这说明智能体并非简单地“丢失信息后胡言乱语”，而是会调整自己的搜索策略——例如更频繁地重新访问相近的查询或重复读取同一来源，以补偿压缩带来的上下文细节缺失。这一发现提示：仅仅以最终任务准确率衡量压缩效果是不够的，压缩方法还会从内部改变智能体的探索–利用平衡，进而影响整个轨迹的形态和运行开销。

## 7. 局限性分析

- **任务覆盖范围有限**：论文的实验全部落在“通过互联网搜索和文档阅读获取事实信息”这一类智能体任务上。代码编辑、GUI 操作、表单填写、状态变更型 Web 任务等具有更强长期依赖和副作用的任务未被检验；这些任务可能对压缩位置的局部性与可逆性有不同要求，结论未必能直接迁移。
- **压缩策略是静态的**：压缩比（默认 20%）、延迟窗口（默认 1 或若干回合）都是固定超参，而非根据任务难度、轨迹长度或缓存压力动态调整。论文虽观察到延迟压缩能恢复性能，但没有回答“如何决定何时延迟、延迟多久最优”这一实际部署问题。
- **代理查询的来源仍依赖模型内部状态**：边界查询和重复预填充查询需要读取模型隐层 query 向量，这在私有 API 或非白盒推理服务中不可用；延迟未来查询又要求事先保留原始 KV 直到未来回合发生。当前方案的适用面仍以白盒、可控推理引擎为主。
- **公平性存在微弱不对称**：Gemma-4 系列使用了鼓励强化搜索的系统提示词（例如明确要求至少 20 次检索），而 Qwen3.5 的提示条件可能不同。作者并未对此做完全对齐，因此跨模型对比压缩方法增益时，需警惕提示词差异带来的混合效应。
- **AM 方法代价未充分量化**：论文指出注意力匹配在多数情况下与令牌驱逐效果相当，但并未系统报告其在推理时额外引入的优化耗时。考虑到智能体在线推理对延迟敏感，AM 的计算开销即使较小，也可能在实际服务中成为不可忽略的负担。

## 8. 总体评价与学术意义

- **核心贡献是视角转换**：论文没有把 KV 压缩仅当作“让注意力近似更快”的数值优化问题，而是把它重新定义为“在线压缩中代理查询的选择问题”。这一提法抓住了智能体场景与静态文档压缩的本质区别——未来查询不可预知、压缩发生在推理主循环内、压缩结果反过来影响智能体未来行为。
- **实证结论具有工程直接可操作性**：对部署者而言，“优先选择延迟的未来回合查询作为代理信号”“令牌驱逐已然足够、不必强求注意力匹配”“压缩会改变智能体检索行为”这三条结论，可以较直接地转化为服务端缓存策略的设计建议，而不需要引入复杂的训练或微调流程。
- **方法论上具有示范性**：论文同时报告任务性能、缓存规模、服务吞吐和轨迹行为四类指标，构建了较完整的在线压缩评估框架。95% bootstrap 置信区间的使用也增强了结果可信度，使之有助于后续工作在该框架下做横向对比。
- **留下的开放问题**：如何设计轻量的“未来查询预测器”来逼近延迟压缩的信息优势，同时保持即时压缩的内存收益；如何在压缩决策中引入自适应延迟和自适应预算；以及如何把代理查询选择框架推广到非 Transformer 混合架构或状态空间模型——这些都是比论文本身更长远且更有价值的研究方向。

总体而言，这是一项定位清晰、实验扎实、结论对实践有指导意义的系统级研究。它证明了在线智能体场景下的 KV 压缩与静态上下文有本质差异，并把“用什么样的代理查询来指导压缩”提升为一个值得单独研究的设计维度，为该方向后续工作奠定了较坚实的实证基础。
