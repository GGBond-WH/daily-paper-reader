## 摘要
查询无关的 KV 缓存驱逐方法会一次性压缩上下文，并将所得缓存复用于任意未来查询，但在严格预算下性能可能急剧下降。现有方法主要改进保留哪些原始 KV 对。我们推出了 RestoreKV，它在相同的总 KV 预算下，通过学习式恢复来补充这种基于选择的方案。我们的关键见解是，尽管因驱逐而丢失的信息是特定于上下文的，但生成其紧凑补集的机制可以在不同上下文之间共享。在上下文预填充之后，几个恢复 token 在单次 LoRA 适配的传递中关注完整 KV 缓存，生成一个紧凑的、以上下文为条件的恢复缓存。基础重要性评分器和驱逐规则保持不变，并且适配器在后续所有查询和解码中均被禁用。RestoreKV 通过参数高效的自蒸馏，从冻结的完整缓存模型进行训练，仅优化 $0.4\%$ 的参数，且无需任务特定调优。在四个主干模型和四个长上下文基准测试中，RestoreKV 显著减少了压缩引起的性能下降。在 Qwen3-4B 上，它在五种基础驱逐方法的 60 个配对、预算匹配设置中改善了 59 个；在 $5\%$ 预算下，它将 RULER-4K 上的 KVzip 从 $38.2$ 提升到 $73.2$。应用于 KVzip+ 时，RestoreKV 在 KVPress Benchmark 上以 $16\times$ 压缩比达到 $86.4$ 的 RULER 准确率，同时在 32K 上下文评估中仅增加不到 $0.5\%$ 的一次性缓存构建开销。我们的项目页面可在 https://paper.pnu-cvsp.com/RestoreKV/ 获取。

## Abstract
Query-agnostic KV cache eviction compresses a context once and reuses the resulting cache for arbitrary future queries, but performance can collapse under tight budgets. Existing methods primarily improve which original KV pairs are retained. We introduce RestoreKV, which complements this selection-based formulation with learned restoration under the same total KV budget. Our key insight is that, although the information lost through eviction is context-specific, the mechanism for generating its compact complement can be shared across contexts. After context prefill, a few restore tokens attend to the full KV cache in a single LoRA-adapted pass, generating a compact, context-conditioned restore cache. The base importance scorer and eviction rule remain unchanged, and the adapters are disabled for all subsequent queries and decoding. RestoreKV is trained through parameter-efficient self-distillation from the frozen full-cache model, optimizing only $0.4\%$ of the parameters and requiring no task-specific tuning. Across four backbones and four long-context benchmarks, RestoreKV substantially reduces compression-induced degradation. On Qwen3-4B, it improves 59 of 60 paired, budget-matched settings across five base eviction methods; at a $5\%$ budget, it raises KVzip from $38.2$ to $73.2$ on RULER-4K. Applied to KVzip+, RestoreKV reaches $86.4$ RULER accuracy at $16\times$ compression on the KVPress Benchmark, while adding less than $0.5\%$ one-time cache-construction overhead in a 32K-context evaluation. Our project page is available at https://paper.pnu-cvsp.com/RestoreKV/

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **问题背景**：大语言模型的长上下文推理严重依赖 KV 缓存，但其随序列长度线性增长，成为推理成本的主要瓶颈。KV 缓存驱逐（KV cache eviction）通过仅保留部分 KV 对来降低内存开销。
- **查询无关（query-agnostic）场景**：在未来的查询未知时，一次性压缩上下文，并将压缩后的缓存复用于任意后续请求。这一场景对缓存压缩的通用性和效率要求更高。
- **现有方法的局限**：当前查询无关驱逐方法（如 KVzip、KVzip+、ContrastKV 等）本质上都是**选择型（selection-based）** 方法——核心问题始终是"在固定预算下哪些原始 KV 对应该被保留"。然而，在激进压缩（严格预算）下，仅靠更优的保留选择仍无法避免严重的性能崩溃。
- **核心洞察**：虽然通过驱逐丢失的信息是**上下文特定的**，但生成其紧凑补集的**机制**可以在不同上下文之间**共享**。这启发了从"选择更好的子集"转向"生成紧凑的补偿信息"的互补视角。
- **整体意义**：RestoreKV 并非替代现有驱逐方法，而是作为一种插件式补充，在同一 KV 预算下用学习得到的恢复缓存弥补选择型驱逐的信息损失，显著缩小与全缓存模型之间的性能差距。

## 2. 论文提出的方法论

**核心思想**：在同一总 KV 预算下，RestoreKV 在驱逐之前生成一个紧凑的、上下文条件化的"恢复缓存"（restore cache），与保留的原始上下文 KV 对共同构成最终缓存。基础评分器和驱逐规则完全保持不变。

**关键技术细节与流程**：

1. **恢复缓存生成**：
   - 设置 n 个可学习的恢复 token 嵌入（默认 n=8）。
   - 上下文预填充后，这些恢复 token 在位置 T+1 至 T+n 处以因果注意力方式访问**完整 KV 缓存**。
   - 在单次"恢复传递"（restore pass）中，仅对注意力/MLP 投影启用 LoRA 适配器（秩 r=8，缩放 α=16），生成 nLH 个上下文条件化的 KV 对（L 层 × H 个头 × n 个 token）。
   - LoRA 仅在恢复缓存生成期间激活；随后的查询处理和解码全部使用原始冻结主干。

2. **预算匹配**（公式 6）：
   - 总 KV 预算 B = ⌊rT·L·H⌋（r 为预算比率）。
   - RestoreKV 从 B 中预留 nLH 个槽位给恢复缓存 Cres，基础驱逐器填充剩余的 B−nLH 个槽位：
     - C̃ = Concat(Evict(C, s, B−nLH), Cres)
   - 最终缓存大小仍为 B，与基础方法完全一致，不增加查询时 KV 内存。

3. **训练目标——自蒸馏**（公式 7-8）：
   - 冻结的全缓存模型作为教师，使用恢复缓存的学生模型匹配教师的答案 token 分布。
   - 损失为对称 KL 散度，对 token 取平均。
   - 仅更新恢复 token 嵌入和 LoRA 参数（约 0.4% 的 4B 模型参数量），骨干和基础评分器冻结。
   - 训练时从 U(0.025, 0.25) 均匀采样 KV 预算比率，使单一恢复机制支持多种预算。
   - 关键：训练使用的查询和教师答案仅用于离线定义蒸馏目标；推理时恢复缓存的生成完全不依赖查询，保持查询无关性。

4. **推理流程**：先对完整 KV 缓存执行一次 n token 的恢复传递生成 Cres，与驱逐器保留的上下文 KV 对组合成最终预算匹配缓存，之后即可复用于任意查询。

## 6. 论文的主要结论与发现

1. **有效性**：RestoreKV 在几乎所有匹配预算的设置下显著降低压缩导致的性能退化，且预算越紧，收益越大。例如 Qwen3-4B 在 5% 预算下将 KVzip 的 RULER-4K 准确率从 38.2 提升至 73.2；应用于 KVzip+ 时在 16 倍压缩下达到 86.4。
2. **通用兼容性**：RestoreKV 不依赖特定选择策略，能作为插件与多种驱逐方法（KVzip、KVzip+、ContrastKV、SnapKV、H2O、Fast KVzip）组合均有效。
3. **机制归因**：恢复收益主要来自**注意力侧的 LoRA 适配**（固定嵌入 + LoRA 达到 71.9，而仅学习嵌入只有 42.1），而非嵌入中记忆的通用信息；完整上下文条件化提供额外增益（+8.8 分）。
4. **上下文注意力的恢复**：RestoreKV 部分恢复了驱逐方法压制的上下文注意力（平均质量从 0.56% 提升到 1.30%），层间分布也更接近全缓存模式。
5. **高效性**：一次性开销极低（<0.5% 压缩时间、0.4% 峰值内存），查询时 KV 预算和解码成本与基础方法完全一致。

## 7. 优点

- **视角创新**：从"选择哪些 KV 对保留"转向"生成一个小型上下文条件化补集"，是对选择型驱逐范式的有效互补而非替代。
- **设计优雅**：保持基础评分器和驱逐规则不变，插件式接入现有流水线；LoRA 仅在一次性恢复传递中激活，不改变推理路径。
- **预算严格匹配**：恢复缓存占用等量 KV 槽位，不增加查询时内存成本，公平性得到保证。
- **训练高效**：仅 0.4% 参数可训练，单 GPU 两小时完成训练，无需任务特定微调，且跨上下文和预算具有泛化能力。
- **实验严谨**：全面的消融设计（组件归因、全上下文条件价值、token 数量、位置偏移控制、训练-推理失配、训练比率范围、种子敏感性）使得结论具有较高的可信度。
- **长上下文外推**：在仅 15K 训练上下文下，对约 104K 的 SCBench 任务仍有稳定改善，显示一定的长度泛化能力。

## 8. 不足与局限

- **跨驱逐器迁移有限**：训练-推理驱逐器失配实验显示，用 SnapKV 训练的检查点在 KVzip 推理下仅获得微弱的跨驱逐器迁移效果（r=0.05 时 42.0 vs. 训练匹配时的 73.2）。这意味着 RestoreKV 需要**针对每个基础驱逐方法单独训练**，增加了部署成本。
- **任务覆盖仍有限**：四个主要基准集中在合成检索、QA 和阅读理解等任务类型，对代码生成、多轮对话、结构化推理等场景的验证不足。
- **与合成缓存方法的比较不够全面**：仅与 Attention Matching（AM-fast）一个合成缓存基线对比，且 AM-fast 在较宽松预算的 LongHealth 上表现更强。与 KV-Distill、Cartridges、VECTOR 等其他合成缓存方法的对比缺失。
- **较小的恢复 token 数量**：默认 n=8，所有实验训练上下文最长 15K token；虽然 SCBench 外推到 104K 仍有效，但更长上下文（如百万级）下的表现尚未验证。
- **未讨论多维复杂场景**：如并发服务中的 KV 缓存管理、前缀共享、投机解码等实际推理系统中的交互影响未被考虑。
- **关于位置索引的注意事项**：恢复 token 占用了上下文结束后的 8 个位置，使后续查询的 RoPE 偏移增加 8；虽然控制实验排除了这一因素的主导作用，但这一设计在需精确保留相对位置信息的应用中可能引入细微偏差。
- **计算开销未在多 GPU 场景验证**：训练和评估均基于单张 GPU，大规模并行训练或部署时的效率特征未被刻画。
