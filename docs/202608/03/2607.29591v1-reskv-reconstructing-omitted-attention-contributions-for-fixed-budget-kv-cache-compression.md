## 摘要
KV缓存压缩对于高效的长上下文推理至关重要。现有的驱逐方法会永久丢弃未选中的令牌，从而移除它们对注意力的整体贡献。基于合并的替代方法能保留更多信息，但可能会扰动本应保持精确的保留键和值。我们观察到，缓存驱逐遗漏的信息可以表述为softmax注意力分子和分母中的残差统计量。基于这一观察，我们提出了ResKV，它将固定的KV预算划分为精确的主缓存和紧凑的残差缓存，以重建被省略令牌的贡献。ResKV让主缓存令牌和残差条目参与相同的softmax归一化，因此残差条目能够恢复注意力的分子和分母质量，而不是作为事后修正。构建时验证代理确定每个层和KV头的残差分配，而解码时动态门则针对单个查询调整残差贡献。在LongBench和RULER上的全面评估，涵盖查询感知和查询无关设置、多种骨干网络、缓存预算以及代表性压缩基线，表明在相同保留KV预算下实现了广泛的改进，同时保持了压缩解码的实际效率，包括峰值内存使用和长上下文解码吞吐量。

## Abstract
KV cache compression is essential for efficient long-context inference. Existing eviction methods permanently discard unselected tokens and consequently remove their aggregate contribution to attention. Merging-based alternatives preserve more information but can perturb retained keys and values that should remain exact. We observe that the information omitted by cache eviction can be formulated as residual statistics in both the numerator and denominator of softmax attention. Based on this observation, we propose ResKV, which divides a fixed KV budget into an exact main cache and a compact residual cache that reconstructs the contribution of omitted tokens. ResKV lets main-cache tokens and residual entries participate in the same softmax normalization, so residual entries restore both attention numerator and denominator mass rather than acting as a post-hoc correction. A construction-time validation proxy determines residual allocation for each layer and KV head, while a decode-time dynamic gate adjusts residual contributions for individual queries. Comprehensive evaluations on LongBench and RULER, covering query-aware and query-agnostic settings, multiple backbones, cache budgets, and representative compression baselines, demonstrate broad improvements under the same retained KV budget while preserving the practical efficiency of compressed decoding, including peak memory usage and long-context decode throughput.

# ResKV 论文总结

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：长上下文大语言模型（LLM）依赖 KV 缓存避免重复计算历史键值，但缓存随上下文长度线性增长，成为推理内存和带宽的主要瓶颈。KV 缓存压缩需要在保留足够历史信息与固定缓存预算之间取得平衡。
- **现有方法的缺陷**：
  - **驱逐式方法**（如 H2O、SnapKV、TOVA、AdaKV）：永久丢弃未选中 token，导致其聚合注意力贡献（softmax 的分子与分母质量）被完全移除。在注意力分散的场景中，大量低分 token 的聚合贡献可能很大，丢失风险尤为突出。
  - **合并式方法**（如 CaM、KVMerger、KeepKV、SemantiCache）：将驱逐 token 的状态折叠进保留条目中，虽然保留更多信息，但会扰动本应保持精确的保留键值，损害精确检索能力。
- **核心观察**：缓存驱逐所遗漏的信息可精确表述为 softmax 注意力中分子和分母两侧的**残差统计量**。若能重建这些统计量，则无需在"完全删除"和"折叠合并"之间二选一。
- **ResKV 的含义**：将固定 KV 预算拆分为"精确主缓存 + 紧凑残差缓存"，以同一预算同时实现精确保留与信息重建，避免驱逐的二元删除，也不扰动精确记忆。

## 2. 方法论：核心思想、技术细节与算法流程

### 核心思想

将固定 KV 预算 `b = m + r` 分为两部分：
- **主缓存（Main Cache）**：`m` 个槽位，精确存储高优先级 token 的原始键值，作为"精确记忆"。
- **残差缓存（Residual Cache）**：`r` 个槽位，以紧凑的残差条目表示被驱逐 token 的聚合注意力贡献。

残差条目与主缓存 token **参与同一 softmax 归一化**，同时恢复注意力分子和分母的质量，而非作为事后输出修正。

### 关键技术细节

1. **残差的形式化定义**
   - 对被驱逐集合 E，其残差统计量为：
     - `Z_E(q) = Σ_{p∈E} exp(a_p(q))`（分母质量）
     - `N_E(q) = Σ_{p∈E} exp(a_p(q)) · v_p`（分子质量）
   - 添加残差后，输出为：
     - `ô(q) = (N_M(q) + N̂_R(q)) / (Z_M(q) + Ẑ_R(q))`

2. **残差条目的构建**
   - 将驱逐集合 E 划分为 r 个簇（通过 Lloyd 迭代最小化簇内键距离，即 key-space consistency 作为查询无关的代理目标）。
   - 每个残差条目 `C_j` 存储三个量：
     - 代表键 `k̄_j`（簇内键均值）
     - 代表值 `v̄_j`（簇内值均值）
     - 人口计数 `c_j = |C_j|`
   - 当 `c_j = 1` 时，残差条目退化为精确保留的 token。

3. **共享 softmax 残差解码**
   - 主缓存 logits：`a_p = ⟨q, k_p⟩ / √d`
   - 残差 logits：`ã_j = ⟨q, k̄_j⟩ / √d + log c_j + log g(q)`
   - 其中 `log c_j` 注入群体人口质量，`g(q)` 为动态门控。
   - 主缓存与残差条目在同一 softmax 中归一化（算法流程见下）。

4. **自适应残差控制（双重机制）**
   - **构建期验证代理**：将观察窗口分为拟合集和验证集，在候选残差预算网格中，仅当残差重建在验证集上显著降低注意力输出重建误差（相对提升超过 δ = 0.01）时，才为对应层/KV头启用残差缓存，实现逐层、逐头的自适应分配。
   - **解码期动态门控**：根据主缓存注意力尖峰程度（`p_max^M(q)`，即主缓存最大注意力权重）调节残差 logits。注意力越集中（尖锐检索峰），残差贡献越被压低；注意力越分散，残差贡献越强。

### 算法流程（文字描述）

**构建阶段**：
1. 形成观察查询，拆分为拟合查询和验证查询。
2. 计算 token 得分，设置近期窗口保护。
3. 构建纯主缓存（r=0），计算验证损失 L_val^0。
4. 对每个候选 r > 0：设置 m = b − r，选择主缓存 M_r，构建 r 个残差条目，计算验证损失 L_val^r。
5. 选择使验证损失最小的 r*；仅当 `L_val^r* < (1 − δ) L_val^0` 时启用残差，否则回退到 r = 0。

**解码阶段**（每步）：
1. 计算主缓存 logits 和主缓存注意力尖峰度 `p_max^M`。
2. 计算动态门控 `g(q)`。
3. 初始化分母 Z 为主缓存分母之和、分子 N 为主缓存分子之和。
4. 对每个残差条目：计算残差 logits（含 `log c_j` 和 `log g`），累加到 Z 和 N。
5. 返回 `ô = N / Z`。

## 3. 实验设计

### 数据集与基准

- **LongBench**：覆盖 16 个真实世界长上下文理解任务，包括单文档 QA、多文档 QA、摘要、少样本学习、合成检索和代码补全。
- **RULER**：受控长上下文检索与聚合测试，报告 13 个任务在 4K 和 32K 上下文长度下的结果。

### 评价设置

- **两种骨干网络**：LLaMA-3.1-8B-Instruct 和 Qwen-2.5-7B-Instruct。
- **两种压缩构建方式**：
  - **查询感知（Query-Aware）**：查询已附加上下文后再压缩。
  - **查询无关（Query-Agnostic）**：仅从可复用上下文构建缓存，查询在压缩后才提供（更贴近实际部署）。
- **四种压缩比例**：ρ ∈ {0.6, 0.7, 0.8, 0.9}，即保留 40%、30%、20%、10% 的 KV 槽位。

### 对比基线

- **H2O**：保留高累积注意力质量 token。
- **SnapKV**：从观察窗口估计 token 重要性。
- **TOVA**：使用近期注意力打分 token。
- **AdaKV**：逐注意力头分配缓存预算。
- **CaM**（合并式代表方法）：将驱逐状态合并进保留条目。

## 6. 主要结论与发现

1. **ResKV 在相同保留 KV 预算下一致优于对应基线**：LongBench 全部 32 个显示配置、RULER 63/64 个显示配置获得改进。
2. **紧预算下收益最大**：10% 和 20% 保留 KV 时，LongBench 提升分别为 1.43 和 1.17 点；RULER 提升分别为 3.47 和 3.66 点。
3. **查询无关设置提升更显著**：RULER 中查询无关设置平均提升 4.54 点，优于查询感知的 2.22 点，说明 ResKV 在实际部署场景（未来查询未知）下更有价值。
4. **分布式证据任务受益最大**：代码补全（RepoBench-P、LCC）、多键检索（Passage Retrieval）、Variable Tracking 等需要分散上下文证据的任务改进最明显。
5. **优于合并方法**：与 CaM 相比，ResKV 通过独立残差缓存实现更强的任务级提升，且不会扰动主缓存。
6. **效率可接受**：峰值内存与压缩基线基本重叠，解码吞吐量略低于 SnapKV 但远高于全缓存，在 128K 上下文下仍保持稳定。
7. **三个组件均有贡献**：移除验证代理、动态门控或共享 softmax 都会导致任务性能下降，验证了设计的必要性。

## 7. 优点

- **视角新颖且理论清晰**：将驱逐遗漏的信息严格形式化为 softmax 分子/分母残差统计量，从注意力计算本身出发设计压缩方案，而非仅凭启发式分数。
- **兼顾精确与压缩**：主缓存保持"精确记忆"，残差缓存以紧凑条目恢复"聚合贡献"，避免二选一困境；`c_j = 1` 时残差退化为精确 token，理论上界明确（附录 A 给出误差界）。
- **双重自适应机制设计精巧**：构建期验证代理实现逐层、逐头残差预算分配；解码期动态门控根据查询的注意力形态实时调节残差权重，两个控制点分别对齐"存多少"和"用多少"。
- **共享 softmax 而非事后修正**：残差条目参与同一归一化，同时恢复分子和分母，与注意力计算原理一致。
- **实验设计公平**：配对比较中保持总预算一致、使用基线相同的得分规则；同时覆盖查询感知/查询无关两种设置，后者更贴近实际部署。
- **效率分析完整**：除精度外还报告了峰值内存、解码吞吐量、可聚类性分析，说明方法不仅"有效"而且"可用"。

- **无多轮运行统计**：单次运行无方差报告，无法评估方法性能的稳定性。

### 方法局限
- **仅预填充后一次性压缩**：残差条目在 prefill 后构建且不刷新，对长生成场景（大量新 token 不断加入）支持有限。论文在"Limitations"中承认此点。
- **残差条目使用均值表示**：均值键值对簇内异构性敏感，更丰富的残差摘要（如低秩近似、多中心）可能进一步提升近似质量。
- **动态门控引入额外超参数**：τ、T_g、g_min 需要调节，论文未充分消融这些超参数的敏感性。
- **解码阶段额外开销**：需额外计算残差分支和动态门控，吞吐量略低于纯驱逐方法，对延迟极敏感的场景可能不友好。
- **查询无关设置下绝对分数仍低**：在 10% 预算、查询无关时，许多任务绝对准确率很低（如 RULER 的 S3 任务约 1.6），ResKV 虽有提升但距离可用仍有很大距离。
