## 摘要
近期关于检索增强生成（RAG）的优化研究利用块级键值缓存复用来避免处理冗长的检索上下文，从而提高效率，但粗粒度块中仍存在显著的信息冗余和噪声。本文通过提出CoinRAG（面向长上下文RAG的上下文信息碎片键值缓存复用），在低预填充延迟约束下优化帕累托前沿，同时最大化准确性。该名称隐喻地反映了我们的核心机制：就像组装小硬币来积累更大的价值一样，CoinRAG组合式地复用离线计算的细粒度碎片缓存，以更语义相关且紧凑的方式高效形成学习到的上下文表示。具体而言，CoinRAG不进行全块编码，而是通过两阶段检索识别检索块中与查询相关的语义单元，并利用块级上下文无缝组装它们的切片键值表示。在LongBench多跳问答任务上的广泛评估表明，CoinRAG显著降低了运营成本，并在标准快速预填充延迟预算下，以新的帕累托前沿和平均5.3%的答案质量（F1）相对提升超越了其他基线。

## Abstract
Recent optimization studies on Retrieval-Augmented Generation (RAG) have exploited chunk-level KV cache reuse to avoid processing long retrieved contexts for higher efficiency, while significant information redundancy and noise still remain in the coarse-grained chunks. This paper optimizes the Pareto frontier under low prefill latency constraints while maximizing accuracy by proposing CoinRAG (Contextualized Information Nugget KV Cache Reuse for Long-Context RAG). The name metaphorically reflects our core mechanism: much like assembling small tokens (or "coins") to accumulate a larger value, CoinRAG compositionally reuses offline-computed, fine-grained nugget caches to form a learned contextual representation efficiently in a more semantically relevant but compact manner. Specifically, instead of full-chunk encoding, CoinRAG identifies query-relevant semantic units within retrieved chunks through two-stage retrieval and seamlessly assembles their sliced KV representations with a chunk-level context. Extensive evaluations on LongBench multi-hop question answering tasks demonstrate that CoinRAG significantly reduces operational costs and outperforms the other baselines with a new Pareto frontier and an average 5.3% relative improvement in answer quality (F1) under a standard fast prefill latency budget.

## 1. 核心问题与整体含义

- **研究背景**：检索增强生成（RAG）是提升大语言模型事实一致性和减少幻觉的主流范式，但当系统以粗粒度（全文或大块文本块）运行时，推理开销巨大，预填充延迟高、计算冗余多。
- **已有优化的不足**：近期研究通过块级 KV 缓存复用（如 TurboRAG、CacheBlend、KVLink）避免重复编码检索上下文，但**粗粒度块中仍包含大量信息冗余和噪声**，相关证据可能淹没在较长的噪声上下文中（"lost in the middle"问题）。
- **核心问题**：在满足低延迟预算（P99 TTFT ≤ 100 ms，作为交互式服务的标准 SLA）的前提下，如何最大化 RAG 的答案准确率。
- **论文整体思路**：借鉴人工作业中"信息碎片（nugget）"的概念（源自 TREC QA 评测），提出在**更细粒度**的信息单元层面构建、检索并复用 KV 缓存——离线从文档块中提取语义完整的文本片段，在线仅组装与查询相关的碎片缓存，从而以更小的上下文长度、更低的延迟获得更高的准确率。

## 2. 方法论

### 2.1 核心思想
- **隐喻**：如"硬币"（coins）组合成更大价值，CoinRAG 组合式复用离线计算的、细粒度的信息碎片 KV 缓存，形成语义相关且紧凑的上下文表示。
- **关键洞察**：以文本跨度（text span）形式提取的碎片，其 KV 表示可以从预计算的全块缓存中直接**切片**获得，保证每个 token 的表示保留了全块编码时的上下文语义，这与孤立编码碎片文本有着本质区别。

### 2.2 技术流程（四大组件）

**（1）离线碎片提取（Offline Nugget Extraction）**

- 使用 LLM（GPT-4o-mini）从每个 512-token 文档块中提取候选碎片。
- 通过三层匹配将候选映射回原文的 token 跨度：
  - **Stage A（精确匹配）**：候选是原文的连续子串，直接接受。
  - **Stage B（模糊匹配）**：在原文中搜索与候选长度相近的整词跨度，取相似度最高者，若超过阈值 τ=0.7 则接受。
  - **Stage C（放弃）**：否则丢弃该候选。
- 每个碎片记录为 `(源块, 起始 token 索引, 结束 token 索引)`，为后续 KV 切片提供指针。

**（2）两阶段在线检索（Two-Stage Online Retrieval）**

- **阶段一**：用稠密检索器（BGE-M3）从语料库中取 top-kc 个候选文档块。
- **阶段二**：仅在这 kc 个块内，对预先提取的碎片按与查询的嵌入相似度排序，取 top-k 个碎片。
- 两阶段设计显著缩小候选池，提升检索精度（消融实验显示比单阶段检索相对提升 9.6–17.5%）。

**（3）上下文化 KV 缓存组合与位置对齐**

- 对每个选中碎片，用其边界索引直接切片预计算的块级 KV 缓存 `Cbi[si:ei]`，获得保留全块上下文语义的碎片 KV。
- 由于各碎片来自不同块、不同位置，RoPE 位置编码不匹配，采用**位置旋转算子** `Rot(C;Δ)` 统一位置：
  - 按原文档顺序保持碎片相对顺序（order-preserving, contiguous alignment），消除中间未检索文本。
  - 第 i 个碎片的位置偏移量：`Δi = |p| + Σ_{j<i}(ej − sj + 1)`。
- 最终上下文缓存为：系统提示缓存 + 各旋转后的碎片 KV 拼接 + 在线计算的查询 KV。

**（4）碎片感知微调（Nugget-Aware Fine-tuning）**

- 为解决非连续缓存段拼接与预训练连续序列之间的训练-推理结构差距，在包含正例和干扰项文档的 QA 数据上，模拟在线碎片提取与组合流程，用标准交叉熵损失微调模型。
- 一次训练成本：约 140 GPU 小时（单卡 RTX PRO 6000）。

## 3. 实验设计

### 3.1 数据集
- 选用 LongBench 中**三个多文档、多跳问答基准**：HotpotQA、2WikiMQA、MuSiQue。
- 多跳、跨文档推理任务直接挑战系统跨块检索与缓存复用能力，适合验证 CoinRAG 的设计目标。
- 训练集来自 IRCoT（共 277,280 个训练实例）。

### 3.2 对比基线
- **Standard RAG**：完全在线编码检索块，无缓存复用。
- **TurboRAG**（代表块级 KV 缓存复用范式，与 Block-attention 设计几乎一致）：预计算并复用整块 KV。
- **CacheBlend**：复用预计算 KV 的同时，选择性重算少量 token 以恢复跨块注意力。
- **KVLink**：在各块中插入可训练链接 token，恢复跨块自注意力。
- 各基线均用相同数据和超参数进行训练以保证公平，并扫描各自的 top-k 或重算比率绘制帕累托曲线。

### 3.3 评估指标
- **准确率**：token 级 F1。
- **效率**：TTFT（首 token 延迟，均值与 P99）、上下文 token 长度（KV 显存占用的直接代理指标）。
- 实验在两种预算下对比：P99 ≤ 100 ms（低延迟 SLA）和无延迟限制。

## 6. 主要结论与发现

- **低延迟预算（P99 ≤ 100 ms）下**：CoinRAG 在全部 3 个数据集上超过所有基线，平均 F1 为 41.7 vs. 最强基线 TurboRAG 的 39.6，**相对提升 5.3%**，同时上下文长度仅为后者的 1.84 分之一。
- **无延迟限制时**：CoinRAG 仍在 2/3 数据集上超过所有基线，3 数据集平均 F1 为 42.7 vs. 最强基线 40.6（相对提升 5.2%），上下文长度平均缩短 6.8 倍，说明**去除噪声和冗余带来的收益超过丢失跨块交互的损失**。
- **长度受限场景**：给定相同上下文长度预算，CoinRAG 的 F1 始终最高；即使无长度限制，其上下文也远短于其他方法（最多比 Standard RAG 短 10.1 倍）。
- **位置对齐**：在较紧的 75 ms 延迟预算下 F1 提升 3.0–8.5%；预算 ≥ 100 ms 时与不对齐基本持平。
- **消融总结**：上下文化 KV 切片（因保留全块语义）和碎片感知微调（因消除结构错配）是贡献最大的两个组件。

## 7. 优点

- **问题定位精准**：抓住了块级 KV 缓存复用中"粒度不够细、噪声仍大"这一关键痛点，从表示粒度层面实现突破。
- **方案设计巧妙**：将碎片表示为原文中的 token 跨度，使得 KV 切片能无缝保留全块上下文语义，避免了孤立重编码的信息损失；同时"按需切片"还节约磁盘存储（仅存碎片覆盖的 token，约省 30%）。
- **两阶段检索实用高效**：先在块级粗筛、再在碎片级精排，兼顾效率与精度，符合大规模语料库的实际需求。
- **实验规范化程度较高**：所有基线统一训练数据、统一微调和评估协议；报告 P99 而非平均延迟，符合真实 SLA 要求；绘制帕累托前沿较全面。
- **分析深入**：附录包含完整示例、逐步骤推理流程、成功/失败模式归类，以及详细的 I/O 和成本说明，可复现性强。
- **实用性**：离线一次性成本换在线低延迟高准确率，适合文档更新频率低的真实业务场景。

## 8. 不足与局限

- **离线成本不可忽视**：KV 缓存存储规模大（394 GB），碎片提取和微调均需一次性投入（数百美元 API 费用 + 140 GPU 小时），对语料频繁更新的场景不友好。
- **模型耦合**：预计算 KV 与特定模型检查点绑定，更换骨干模型或修改架构须全量重做离线流程。
- **检索召回率是上限**：答案质量受块级和碎片级检索 recall 约束，检索失败则无法恢复（案例 Type-3′ 即为此类）。
- **跨块注意力缺失**：不同块来源的碎片在编码时互不交互，是 TurboRAG 式块级缓存的共性局限；CacheBlend 等跨块注意力恢复技术尚未在 CoinRAG 中集成。
- **评测覆盖面有限**：仅 3 个多跳 QA 数据集，未涵盖单跳、长文档内部推理、对话式 RAG、时效性知识等场景；且假设查询之间无文档重叠，未考虑跨查询缓存复用。
- **安全风险**：在线生成的答案仍可能关注到缓存中的恶意内容（如提示注入），文中仅提及但未系统研究。
