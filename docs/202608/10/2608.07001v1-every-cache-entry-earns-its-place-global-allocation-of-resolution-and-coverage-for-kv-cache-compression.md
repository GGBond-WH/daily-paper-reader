## 摘要
随着大语言模型（LLMs）处理越来越长的上下文，KV缓存的存储和重复访问已成为主要瓶颈。现有的KV缓存压缩方法依赖预定义的固定压缩规则，并且通常围绕token驱逐或合并来开发。因此，缓存资源既不能在层、头和上下文槽位之间自由流动，也无法被联合分配以平衡局部分辨率和信息覆盖范围。为此，我们提出GraceKV，一种在KV缓存压缩中全局分配分辨率和覆盖范围的方法，并将压缩过程形式化为在固定缓存预算下的全局资源分配问题。GraceKV将每个“层-KV头-槽位”组合视为一个原子单元，并构建原型树。叶节点对应token级别的KV条目，而每个内部节点使用一个原型来压缩其子节点所覆盖的KV空间。树中一组不重叠的节点构成该原子单元的表示。添加新树的根节点可扩展信息覆盖范围，而拆分选中的节点可提高局部分辨率。所有候选操作在全球范围内竞争共享的缓存预算。最终，所有树中保留的节点构成压缩后的KV缓存。该过程在全球范围内自适应地决定原子单元之间的缓存资源分配以及分辨率与覆盖范围之间的平衡。GraceKV无需额外训练，整个压缩和推理过程均在GPU上执行。在多种长上下文任务和压缩比下的系统实验表明，GraceKV在32项设置中的24项中排名第一，并且在高达128倍压缩下仍保持稳健。这些结果验证了全局预算分配在协调信息覆盖范围和局部分辨率方面的有效性。

## Abstract
As large language models (LLMs) process increasingly long contexts, KV cache storage and repeated access have become a major bottleneck. Existing KV cache compression methods rely on predefined, fixed compression rules and are typically developed around either token eviction or merging. As a result, cache resources can neither flow freely across layers, heads, and context slots, nor be jointly allocated to balance local resolution and information coverage. Therefore, we propose GraceKV, a global approach for the allocation of resolution and coverage in KV cache compression, and formulate the compression process as a global resource allocation problem under a fixed cache budget. GraceKV treats each layer-KV head-slot combination as an atomic unit and builds a prototype tree. Leaf nodes correspond to token-level KV entries, while each internal node uses a single prototype to compress the KV space covered by its children. A set of non-overlapping nodes in the tree forms the representation of an atomic unit. Adding the root of a new tree expands information coverage, whereas splitting a selected node improves local resolution. All candidate actions compete globally for a shared cache budget. Finally, the nodes retained across all trees form the compressed KV cache. This process adaptively determines the allocation of cache resources among atomic units globally and the balance between resolution and coverage. GraceKV requires no additional training, and the entire compression and inference process is performed on the GPU. Systematic experiments across diverse long-context tasks and compression ratios show that GraceKV ranks first in 24 of 32 settings and remains robust up to 128-fold compression. These results validate the effectiveness of global budget allocation in coordinating information coverage and local resolution.

# 论文总结：GraceKV —— KV缓存压缩的全局资源分配方法

## 1. 核心问题与研究动机

- **背景**：大语言模型（LLM）处理长上下文时，KV 缓存的存储占用随上下文长度线性增长，且每个解码步骤都要反复访问，成为 GPU 显存与访存开销的主要瓶颈。
- **现有方法的缺陷**：
  - 现有压缩方法（token 驱逐与 KV 合并）依赖**预定义的固定压缩规则**，资源无法在层（layer）、注意力头（KV head）、上下文槽位（slot）之间自由流动。
  - 已有方法即使引入层/头级别的自适应性，仍需**预先指定分配粒度或局部配额**，无法联合协调"局部分辨率"与"信息覆盖范围"。
- **核心问题**：如何让有限的缓存资源自适应地流向更有价值的位置，在全球范围内同时优化信息覆盖与局部表示精度。
- **论文答案**：将 KV 缓存压缩形式化为**固定预算下的全局资源分配问题**，提出 GraceKV 方法。

## 2. 方法论

### 2.1 核心思想
- 将每个"层–KV头–槽位"组合视为**原子单元**，为其构建**渐进可细化的原型树（prototype tree）**。
- 叶节点 = 原始 token 级 KV 条目；内部节点 = 用单个原型（prototype）压缩表示其子树覆盖的连续区间；根节点 = 用单个原型表示整个槽位。
- 一个前沿（frontier）节点集合即代表该原子单元在某分辨率下的缓存表示。
- 两种基本操作：
  - **Add**：添加新树的根节点，扩展信息覆盖范围；
  - **Split**：拆分选中节点，提高局部分辨率。
- 所有候选操作**共享同一全局预算**，通过全局竞争决定最终保留节点，从而同时实现跨层、跨头、跨上下文的资源分配，以及覆盖范围与分辨率之间的动态平衡。

### 2.2 关键技术细节

1. **曲率引导的语义槽切分**
   - 将归一化残差隐藏状态视为沿 token 位置的轨迹，计算多层多尺度的余弦曲率 κ，并结合 token 惊吓度（surprisal）构造边界分数。
   - 用动态规划（DP）在边界奖励、槽内表示离散度、槽长惩罚之间做全局权衡，得到共享的连续槽划分（默认槽长目标 64，范围 16–128）。

2. **RoPE 一致的原型构造**
   - 将 post-RoPE key 反旋转到统一坐标系、取均值后再旋转回代表位置，避免不同旋转坐标系直接平均的失真。
   - Value 原型用 token 价值（加 10% 均匀基底）加权。
   - 通过 key 方向一致性（coherence）修正有效多重性 meff，解码时注意力 logit 加上 log meff 项作为修正。

3. **原型失真度量**
   - 用探针（probe）集合计算原区间与原型之间的注意力分配误差和 value 聚合误差，并以注意力质量加权，避免低频访问区间因局部误差大而获得过高优先级。

4. **自底向上的价值流（Value Flow）**
   - 直接相关性：问题/序列尾部探针的注意力概率。
   - 多跳相关性：在采样层的 token 注意力图上做 hop 级衰减传播（默认 2 跳，λgraph = 0.3）。
   - 节点价值由 token 价值自底向上汇聚，满足精确守恒。
   - 层–KV头敏感性：结合静态输出投影强度与输入条件动态输出强度，作为该头所有操作的敏感性乘子。

5. **效用引导的预算流（Budget Flow）**
   - **Singleton floor（单例保护层）**：先用宽度 7 的 max-pooling 和跨头共识筛选高价值 token，按路径实际消耗的物理条目计费，预算上限为可分配基数的 60%，补偿贪心分配对非平滑收益的低估。
   - **全局竞争**：所有 Add/Split 操作按单位成本边际效用 U(a)=Δ(a)/c(a) 进入同一最大优先级队列，逐次执行最高效用操作，直到预算耗尽。
   - 候选操作的边际收益 = 节点价值 × 失真减少量 × 头敏感性；成本 = 新增物理 KV 条目数。

6. **物理缓存输出**
   - 最终保留的所有前沿节点（含单例层与最近窗口）打包为 ragged cache，直接在 GPU 上解码。
   - 当压缩比 x=1 时，所有树可完全展开为 token 叶节点，**精确恢复 FullKV**。

## 3. 实验设计

  - **LongBench**：单文档问答、多文档问答、摘要、少样本学习；

- **消融与跨骨干验证**：Llama-3.1-8B-Instruct、Qwen2.5-14B-Instruct、Mistral-7B-Instruct-v0.3、Qwen2.5-3B-Instruct。

- **评价指标**：QA 用 F1，摘要/少样本用 Rouge-L，聚合/检索用 Set Recall，分值统一 ×100。

## 5. 实验数量与充分性

- **主实验（32 组设置）**：LongBench 24 组（4 任务 × 6 压缩比）+ RULER 8 组（2 任务 × 4 预算），GraceKV 在 32 组中 24 组排名第一，LongBench 21/24 第一。

- **系统效率实验**：跨上下文长度（6K–30K）的显存/延迟曲线，以及相同预算下与 StreamingLLM、SnapKV 的物理条目/延迟对照。
- **充分性评估**：整体实验设计较为充分且公平——所有方法共享相同输入、模板、预算口径与评估管线，物理缓存条目口径统一；覆盖任务类型多样（覆盖定位、跨区联系、分布式覆盖、精确恢复等不同信息需求）。跨骨干、多压缩比、多任务的组合较全面地验证了方法的稳健性与泛化性。

## 6. 主要结论与发现

1. **全局分配更有效**：在相同物理条目预算下，GraceKV 比固定驱逐、固定合并与局部自适应方法更有效地组织上下文信息。
2. **跨任务与压缩比稳健**：从 4× 到 128× 性能平滑下降，而部分基线在特定任务或高压缩比下急剧退化。
3. **固定策略存在显著任务依赖**：偏合并/覆盖的方法在聚合任务上强、在检索上弱；偏保留原始 token 的方法反之。GraceKV 通过统一覆盖–分辨率分配空间获得更均衡的表现。
4. **各组件均有贡献**：Multi-Resolution 与 Global Allocation 影响最大；问答任务对组件更敏感，摘要任务更宽容。
5. **单例层必要性得到验证**：完全禁用单例层（α=0）导致 8× 与 64× 下 F1 分别下降约 1.05 和 1.52 分，证实贪心分配确实会低估高价值 token 的非平滑收益。
6. **x=1 时精确恢复 FullKV**，压缩与无损方案统一在同一表示空间内。

## 7. 优点

- **创新视角**：将压缩重构为全局资源分配问题，打破"先定规则与配额、再做压缩决策"的范式。
- **统一表示空间**：Add（覆盖）与 Split（分辨率）共享同一物理条目预算，实现跨层、跨头、跨区域的自由竞争，无需预定义任何层/头/槽配额。
- **数学建模细致**：RoPE 一致原型、有效多重性校正、注意力质量加权的失真度量、价值流精确守恒等设计均有明确的推导与动机。
- **工程实用性强**：无需训练、全 GPU 执行、无 CPU 回退；物理缓存为真实压缩（非掩码模拟），且可精确恢复 FullKV。
- **实验全面且公平**：多模型、多任务、多压缩比、多组件消融、超参敏感性、系统效率与摊销分析齐备；统一预算口径增强了对比可信度。

## 8. 不足与局限

- **无法保证全局最优**：作者明确承认采用贪心边际效用分配，在组合优化意义下不能保证全局最优；精确搜索空间随树深度和树数量指数增长，无法满足在线推理延迟要求。
- **一次性构建开销**：原型树构建带来约 2.35 秒延迟和约 8% 峰值显存开销，当前实现未做底层/硬件级优化（并行建树、算子融合、专用 kernel 等）。
- **缓存复用受限**：压缩缓存依赖具体问题（question-conditioned），新问题需要在同一文档上重新构建；对跨问题复用仅提出展望而未实现验证。
- **效率评测范围有限**：系统效率实验仅报告了单卡、单 batch、单一模型的延迟/显存数据，未覆盖高并发、长生成、批量推理等生产场景。
- **部分设置未达最优**：在 RULER 聚合任务和少数 LongBench 设置中 GraceKV 并非第一，说明在"均匀分布型"任务上精细分配的优势有限。
- **超参默认值有一定任务偏向**：如失真权重在 8× 下 0:1 反而最好、64× 下默认 0.25:0.75 最好，说明存在预算依赖的最优配置，默认值选择带有权衡性质。
