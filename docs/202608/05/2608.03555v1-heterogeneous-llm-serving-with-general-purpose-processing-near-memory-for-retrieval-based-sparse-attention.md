## 摘要
本文提出了一种异构解码阶段服务系统，将KV缓存从GPU内存中移出，其动机是近期前沿LLM为处理百万token上下文而采用的基于检索的稀疏注意力机制。它将解码步骤按操作类型划分：GPU节点持有模型权重并执行投影和MoE层，而近内存计算（PNM）节点持有KV缓存和索引键，并执行所有读取它们的操作。我们首先表明，先前的PIM和PNM设计背后的假设对这些操作不再成立，并针对此类节点提出了四个设计要求。基于这些要求，我们提出了KARAT（面向基于检索注意力的KV缓存驻留加速器），这是一个满足所有四个要求的通用PNM设计。KARAT设备将大容量LPDDR与为检索索引器定制的通用计算相结合，实现了超出为低强度GEMV构建的PIM/PNM设计所针对的操作强度，同时适应了固定功能单元在演进中无法支持的多样化稀疏注意力算法。为了减少两种设备类型在微批次之间交替时的流水线气泡，我们进一步提出了机会性细粒度微批次调度（OFMS），该调度将专家全对全通信隐藏在另一个微批次的GEMM之后，以及上下文长度感知的微批次重新平衡（CMR），该机制在上下文长度存在差异的情况下平衡其token数量。在三种最先进的模型和真实的智能体轨迹上，我们提出的系统在服务水平目标下将每TDP吞吐量比纯GPU基线提升了2.09-6.13倍，并运行免训练的稀疏注意力方法，获得了1.36-3.21倍的改进。

## Abstract
This paper presents a heterogeneous decode-phase serving system that relocates the KV cache out of GPU memory, motivated by the retrieval-based sparse attention that recent frontier LLMs adopt to serve million-token contexts. It partitions a decode step by operation type: GPU nodes hold the model weights and execute the projections and MoE layers, while processing-near-memory (PNM) nodes hold the KV cache and index keys and execute every operation that reads them. We first show that the assumptions behind prior PIM and PNM designs no longer hold for these operations, and derive four design requirements for such a node. From these requirements, we propose KARAT (KV-cache-resident Accelerator for Retrieval-based ATtention), a general-purpose PNM design that is the design point meeting all four. A KARAT device combines large LPDDR capacity with general-purpose compute sized for the retrieval indexer, serving an operational intensity beyond what PIM/PNM designs built for low-intensity GEMV target while accommodating diverse sparse attention algorithms that fixed-function units cannot support as they evolve. To reduce pipeline bubbles as the two device types alternate between micro-batches, we further propose opportunistic, fine-grained micro-batch scheduling (OFMS), which hides expert all-to-all behind the other micro-batch's GEMMs, and context-length-aware micro-batch rebalancing (CMR), which equalizes their token counts despite the variance in context length. Across three state-of-the-art models and real agentic traces, our proposed system improves throughput per TDP under a service-level objective by 2.09-6.13x over a GPU-only baseline and runs training-free sparse attention methods with 1.36-3.21x improvements.

- **长上下文与智能体负载的兴起**：LLM 越来越多地服务于智能体（agentic）型工作负载，其上下文在多轮交互中单调累积，真实轨迹中 P99 上下文长度达 198K–791K tokens，且每轮约 94–97% 的 token 命中前缀缓存。解码阶段每步都要对整个上下文做注意力，导致 KV 缓存成为容量和带宽的双重瓶颈。
- **检索式稀疏注意力的新范式**：前沿模型（如 GLM-5.2、DeepSeek-V3.2、MiniMax-M3）采用检索式稀疏注意力，通过索引器（indexer）每步选出 top-k 相关 token，将 KV 读取量降低 6.6–32×，但同时要求完整 KV 缓存和索引键必须驻留内存——78–137 GB/百万 token。这使瓶颈从带宽转向容量。
- **现有方案的局限**：
  - 纯 GPU 方案中 KV 缓存与数百亿参数的 MoE 权重争抢 HBM 容量，批大小受限，内存带宽无法有效利用。
  - 将 KV 缓存卸载到主机内存或 CXL 附加内存只是扩容，不迁移计算，O(L) 索引扫描仍跨越带宽受限链路。
  - 既有 PIM/PNM 设计基于低操作强度（OI）和固定形式 MHA/GQA 的假设，无法支撑检索式稀疏注意力场景（OI 4–128）的多样化算法。

## 2. 论文提出的方法论

### 2.1 核心思想

将解码步骤按操作类型划分为异构流水线：
- **GPU 节点**：持有模型权重，执行投影（projection）和 MoE 层（计算密集型）。
- **KARAT 节点**：持有 KV 缓存和索引键，执行所有读取这些数据的操作（索引器扫描、Gather、Attend 等，内存密集型）。

### 2.2 KARAT 设备设计

基于四个设计需求（R1 容量、R2 带宽、R3 计算、R4 通用性），KARAT 设备的设计要点：

- **内存选型**：对比 DDR5、GDDR6、HBM3 和 LPDDR5X 后，选择 LPDDR5X——其容量/瓦为 HBM3 的 19 倍，带宽/瓦为其 0.8 倍，是唯一同时满足 R1 和 R2 的内存类型。单设备配置 512 GB LPDDR5X、带宽 1.2 TB/s。
- **计算配置**：18 个 GPNM 核心（GPU SM 类似），FP8 下 250 TFLOPS，BF16 下 125 TFLOPS，脊点（ridge point）为 208 FLOPs/byte，高于索引器 OI 范围 4–128，避免计算瓶颈。核心数通过扫描延迟和功耗曲线确定——超过 18 核收益递减。
- **通用性**：采用可编程 GPNM 核心而非专用固定功能单元，以支持不断演进的多样化稀疏注意力算法（不同评分函数、选择粒度、索引器节奏等）。
- **节点组成**：32 个 KARAT 设备组成一个 KARAT 节点，功耗 5.6 kW，与 8 卡 GPU 节点持平，但内存容量为 16 TB vs 1.13 TB（14×），内存带宽同为 38.4 TB/s。
- **KV 放置策略**：一个请求的全部 KV 缓存和索引键放在同一 KARAT 设备上（home device），使 SCORE 到 ATTEND 的全部阶段在本地完成，避免跨交换机传输。

### 2.3 微批次调度优化

- **OFMS（Opportunistic, Fine-grained Micro-batch Scheduling）**：针对静态粗粒度调度（SCMS）的局限，当专家 all-to-all 通信使 GPU 空闲时，机会性地提前启动另一微批次的输出投影等操作，将通信隐藏在 GEMM 之后。采用完全去中心化的实现，仅检查本地队列头部即可决策，不引入额外同步。
- **CMR（Context-length-aware Micro-batch Rebalancing）**：针对上下文长度的巨大方差，每当有请求完成或新请求加入时，将每个设备上的请求按上下文长度降序排序，贪心地分配到累计 token 数较少的微批次，使两个微批次的 token 计数均衡。计算开销极小（仅需排序），且不搬移任何数据。

### 2.4 系统配置搜索

在等功耗和 SLO 约束下，通过网格搜索确定 GPU:KARAT 节点比、专家并行度（EP）、注意力张量并行度（TP），以最大化吞吐量。

## 6. 论文的主要结论与发现

1. **性能优势**：KARAT 在模型原生稀疏注意力场景下，每 TDP 吞吐量比 GPU-only 提升 2.09–6.13×（几何均值 2.23×），比 HiSparse 提升 1.14–2.18×，比 Duplex 提升 1.61–4.83×，比 SPNM 提升 1.23–1.39–（至远超，视模型而定）。加速随上下文长度增加而增大。
2. **免训练方法**：KARAT 无需硬件变更即可支持各类免训练稀疏注意力（Quest、STARC、MagicPIG），提升 1.36–3.21×；而 SPNM 由于固定功能限制，对 MagicPIG 几乎无法加速。
3. **稠密注意力**：KARAT 也获得 1.24–1.32× 提升，但 AttAcc 更高（1.79–2.05×），因其专为低 OI 稠密注意力设计。
4. **调度优化的贡献**：禁用 OFMS 平均降低吞吐量 16%，禁用 CMR 降低 5%，两者都提升 GPU 和 KARAT 设备利用率。
5. **容量不够，计算也得够**：SPNM 与 KARAT 具有相同 LPDDR5X 容量，但性能只有 KARAT 的 ~0.53 倍，说明仅增加容量不足，计算吞吐必须跟上工作负载的操作强度。
6. **最佳配置变化**：引入 KARAT 后最优 EP 度从 64 降至 16–32（减少 all-to-all 开销），且对更长上下文的负载需要更多 KARAT 设备。

## 8. 不足与局限

- **无真实硬件验证**：KARAT 仅通过模拟器评估，未流片或 FPGA 原型验证；GPNM 核心的延迟/功耗数据来自 H200 MIG 缩放，其精度存疑。
- **能耗模型简化**：功耗估算基于 H200 的实测功率替换内存能量，LPDDR5X PHY 开销采用比例折算，可能与真实值有偏差。
- **对比基线参数有利假设**：如 HiSparse 采用其报告的最大命中率 95%，并假设传输按数据大小计入 PCIe 带宽，这些条件在实际系统中可能难以达到。
- **稀疏注意力对质量的影响未讨论**：论文只关注吞吐量和延迟，未评估稀疏注意力在智能体任务上的回答质量是否受影响，也未与传统稠密注意力输出质量对比。
- **扩展性边界未充分探索**：实验限于 8 节点规模（44.8 kW），对更大规模集群中网络拓扑、跨节点通信瓶颈、KARAT 设备间负载均衡的结论可能不完全适用。
- **专家偏斜评估仅用单一公开数据集**：偏斜实验仅使用一个工作负载（来自公共轨迹数据集的最偏斜编码场景），泛化性有限。
- **未涉及多租户和混合模型场景**：实际服务系统中多模型、多租户共存时的资源分配和 KV 缓存隔离问题不在论文范围内。
