## 摘要
长上下文推理中的大语言模型受到键值缓存随序列长度线性增长的制约。虽然剪枝提供了一种缓解手段，但现有方法通常确定查询特定的令牌重要性，无法在未见过的查询之间复用。与此不同，我们提出了TaskPress，一个用于任务引导、查询无关的KV缓存驱逐的框架。TaskPress不是针对单个查询优化缓存，而是基于高层任务指南构建一个可复用的记忆表示。该指南在预填充阶段充当元查询，在下游查询发出之前过滤不相关的令牌。此外，TaskPress利用量化缩放因子作为零成本信号来检测有影响力的表示离群值，为令牌重要性提供了高效的代理。在长上下文输入的各种任务上进行的实验表明，TaskPress能够高效地创建跨多样查询的紧凑、可复用缓存。

## Abstract
Long-context inference with large language models is constrained by the linear growth of the key-value cache to sequence length. While pruning offers mitigation, prevailing methods determine query-specific token importance that cannot be reused across unseen queries. In contrast, we introduce TaskPress, a framework for task-guided, query-agnostic KV cache eviction. Instead of optimizing the cache for a single query, TaskPress constructs a reusable memory representation conditioned on a high-level task guide. The guide functions as a meta-query during prefill to filter irrelevant tokens before downstream queries are issued. In addition, TaskPress leverages quantization scale factors as a zero-cost signal for detecting influential representation outliers, providing an efficient proxy for token importance. Experiments on conducted on various tasks with long context input demonstrate that TaskPress efficiently creates a compact, reusable cache across diverse queries.

## 1. 核心问题与研究动机

- **背景**：大语言模型（LLM）的长上下文推理能力持续扩展（可达数百万 token），但 Transformer 推理过程中缓存的键值对（KV cache）随序列长度线性增长，造成严重的内存开销，甚至超过模型权重本身，成为推理吞吐量和延迟的主要瓶颈。
- **现有方法的缺陷**：
  - **查询相关方法（Query-Dependent）**：如 SnapKV、PyramidKV、Quest 等，利用具体查询的注意力分布动态计算 token 重要性并驱逐低分 token。压缩后的缓存**强绑定于特定查询**，无法复用于新查询，在多查询、多轮对话场景下需要重复进行昂贵的 prefill 计算。
  - **查询无关重构方法（Query-Agnostic Reconstruction）**：如 KVZip，通过上下文重构提高缓存可复用性，但会将提示长度翻倍，产生约 O(Lc²) 的二次方计算开销，效率极低。
- **核心洞察**：实际工作负载往往围绕"任务"展开，同一任务下会有多个查询。与其针对单个查询优化缓存，不如**构建一个以"任务"为粒度的、查询无关的可复用压缩缓存**，使不同查询共享同一压缩结果。

## 2. 方法论：TaskPress 框架

### 2.1 总体思路

TaskPress 将 KV 缓存剪枝从"查询时（query-time）"解耦到"任务时（task-time）"。在 prefill 阶段引入一个**任务指南（Task Guide）**作为"元查询（meta-query）"，通过计算指南与上下文之间的交叉注意力来筛选重要 token，构建可复用的压缩缓存；之后下游所有查询直接使用该缓存，无需重新 prefill 或重新驱逐。

### 2.2 核心机制

- **任务引导的 Key 重要性（Task-Guided Key Importance）**：
  - 将任务指南（长度 Lt）拼接至上下文（长度 Lc）输入模型，计算任务 token 与上下文 token 之间的注意力矩阵 A ∈ R^(Lt×Lc)。
  - 对注意力得分沿任务维度聚合，并用 1D 平均池化（核大小 K）捕获局部依赖，得到第 i 个 context token 的任务引导分数：
    - sᵢ_key = (1/K) Σₖ Σⱼ Aⱼ,ᵢ₊ₖ
  - 该分数仅反映 Query-Key 交互，衡量的是 Key 的结构性可检索性。
- **量化缩放因子作为 Value 重要性（Quantization Scale as Value Importance）**：
  - 关键观察：激活值离群点（outlier）通常对应高信息密度的重要特征。
  - 在 per-token 量化方案下，缩放因子 γᵢ = max(|vᵢ|) / (2^(b-1) - 1)，因位宽 b 为常数，γᵢ 与 value 的最大幅值成正比。
  - 因此直接使用 γᵢ 作为 value 的离群分数 sᵢ_value = γᵢ。
  - **零成本优势**：量化已是业界部署 LLM 的默认手段，缩放因子已存在于内存中，无需额外计算。
  - 实验验证：缩放因子与 value 范数的 Pearson 相关系数达 0.79 ± 0.10，而与注意力分布的相关系数仅 0.06 ± 0.23，说明它捕获的是正交的互补信息。
- **KV 重要性融合（Multiplicative Scoring）**：
  - 最终保留分数为 Key 分数与 Value 分数的元素级乘积：
    - sᵢ = sᵢ_key · sᵢ_value
  - 乘性交互要求 token 同时满足两个条件：任务对齐的注意力空间中结构可检索（高 Key 分）且在语义上信息丰富（高 Value 分）。
  - 对每个注意力头独立选择分数最高的 top-k 索引作为保留子集。

### 2.3 任务指南的构建

- **零样本任务指南初始化（Zero-shot Guide）**：对已知任务，直接使用现成 LLM（如 Gemini）生成 2-3 句话的任务描述，无需人工优化即可作为强基线。
- **进化式任务指南发现（Evolutionary Guide Discovery）**：
  - 针对未知/动态任务，从少量校准查询集（D_cal）中推断用户意图，通过进化算法迭代优化任务指南。
  - 算法流程：初始化候选池（由 LLM 根据校准查询生成 N 个候选）→ 基于校准集下游任务精度评估适应度 → 保留 Top-K 候选 → 通过 LLM 变异/交叉生成新候选 → 迭代 G 代 → 返回最优指南 T*。
  - 变异策略包含"查询驱动的定向改写"和"大胆的结构性重构"；交叉策略保持父对象核心措辞、拼接互补子句。
  - 该框架也可用于进一步优化零样本生成的任务指南，带来额外的准确率提升。

## 6. 主要结论与发现

- 任务指南作为元查询，能够有效聚合未来查询的语义范围，相比具体查询产生**更泛化的上下文覆盖**，实现查询无关的 KV 缓存压缩。
- **零样本任务指南已具备强竞争力**：在 LongBench 上，TaskPress 在 50% 和 75% 驱逐率下均取得最高的平均准确率（如 LLaMA-3.1-8B 上 75% 驱逐率 43.08 vs KVZip 38.24 vs SnapKV 39.37）。
- **进化式指南发现有效**：在未知任务场景下，从查询集自动推断的任务指南优于查询相关基线（SnapKV）；对已知任务的零样本指南进行进化优化带来一致增益（最高 +3.08）。
- **量化缩放因子是高效的 Value 重要性代理**：与 value 范数高度相关且与注意力分布正交，组合后可提升准确率。
- **效率优势显著**：驱逐阶段线性复杂度 O(Lt·Lc) 远低于重构方法的 O(Lc²)（80 倍延迟改善）；多查询场景下端到端延迟优于查询相关方法的两种策略（延迟优化 / 内存优化），并同时保持 5 倍更低的内存占用。
- **与 ThinK 互补**：TaskPress（token 级剪枝）与 ThinK（通道级剪枝）组合可在 75% 总驱逐率下达到接近不压缩的性能。

## 7. 主要优点

- **概念创新**：首次明确将 KV 缓存压缩从查询粒度提升到任务粒度，提出了"元查询"思想。任务指南的引入在直觉上清晰有力（高层任务描述比具体查询更稳健、覆盖更广）。
- **零成本信号复用**：将量化过程中已计算的缩放因子作为值重要性信号，是巧妙且实用的设计，在保证性能的同时不引入额外计算。
- **完整的任务指南构建方案**：既有零样本快速初始化（适用于已知任务），又有进化搜索自动发现（适用于未知任务），兼顾了实用性与泛化性。
- **效率分析详尽**：论文不仅报告准确率，还对 TTFT、TPOT、吞吐量、峰值内存、驱逐延迟、多查询端到端延迟进行了全面评估，证明 TaskPress 的实际部署价值。
- **消融设计严谨**：对 Key/Value 分数各自的贡献、聚合方式、指南粒度、措辞鲁棒性、指南来源模型等因素均进行了系统分析。

## 8. 不足与局限

- **任务依赖（Task-Dependent）**：虽然查询无关，但压缩缓存仍严格受限于任务指南的语义范围。若用户查询严重漂移（如在同一上下文中从摘要任务转向编程任务），压缩缓存可能丢失必要信息，性能下降。
- **密集信息场景失效**：在 RULER MK-2/3（"needle inside needles"）这类含有大量目标实体的极稠密场景中，softmax 归一化的交叉注意力会将注意力质量摊薄，导致单目标分数降至背景噪声以下。文中实验显示 MK-2/3 准确率显著低于其他子任务，尽管作者指出实际数据极少如此极端。
- **对量化统计的依赖**：TaskPress 的核心信号之一来自量化缩放因子；在全精度（FP16/BF16）部署场景中需动态计算 per-token 最大绝对值，虽开销不大（约 2.7% 额外 prefill 时间），但打破了"零成本"声明。
- **进化搜索成本虽是一次性但不可忽略**：约 25 分钟的校准流程（含 API 调用）对新任务上线仍有延迟；且校准集来自测试集的做法在真实部署中不一定可行。
