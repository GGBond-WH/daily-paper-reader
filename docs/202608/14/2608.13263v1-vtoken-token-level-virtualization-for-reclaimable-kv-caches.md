## 摘要
大型语言模型服务面临一个关键的内存瓶颈：KV缓存随序列长度和批处理大小而增长。PagedAttention使用固定大小的内存块来减少分配器级别的碎片，但最近的KV驱逐算法以比块级管理更细的令牌粒度运行。这种不匹配导致块内碎片，使大量已分配的KV内存无法回收。我们提出了vToken，一个轻量级的令牌级虚拟化层，它将逻辑令牌的活跃性与物理块的放置解耦。vToken通过令牌表间接寻址维护稳定的逻辑令牌视图，并通过异步重新打包活跃令牌来实现物理回收。该设计保留了PagedAttention内核和CUDA Graph兼容性。我们在vLLM中实现了vToken，并使用H2O、Random和Scissorhands在多种模型上进行了评估。与配对的Naive-Evict基线相比，vToken将每个请求保留的KV块减少了27.2%–72.3%，并将SLA约束的吞吐量提高了最多1.37倍。在受限的活跃KV预算下，它将最大可行并发度提高了最多2倍，同时将每策略的集成足迹从500多行减少到不足50行。

## Abstract
Large language model serving faces a critical memory bottleneck: the KV cache grows with sequence length and batch size. PagedAttention uses fixed-size memory blocks to reduce allocator-level fragmentation, but recent KV eviction algorithms operate at a token granularity finer than block-level management. This mismatch causes intra-block fragmentation, leaving a large fraction of allocated KV memory unreclaimable. We present vToken, a lightweight token-level virtualization layer that decouples logical token liveness from physical block placement. vToken maintains a stable logical token view through token-table indirection and realizes physical reclamation by repacking live tokens asynchronously. The design preserves PagedAttention kernels and CUDA Graph compatibility. We implement vToken in vLLM and evaluate it with H2O, Random, and Scissorhands across models. Compared with a paired Naive-Evict baseline, vToken reduces retained KV blocks per request by 27.2\%--72.3\% and improves SLA-constrained throughput by up to 1.37$\times$. Under a constrained active-KV budget, it extends the maximum feasible concurrency by up to 2$\times$, while reducing the per-policy integration footprint from 500+ lines to under 50.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **背景**：大语言模型（LLM）推理服务中，KV 缓存随序列长度和批次大小线性增长，成为主要内存瓶颈。PagedAttention 采用固定大小块（block）管理 KV 缓存，以降低分配器级外部碎片，并支持高效注意力内核。
- **问题**：近年出现的 token 级 KV 逐出算法（如 H2O、StreamingLLM、Scissorhands 等）以单个 token 为粒度决定保留/丢弃，而底层运行时仍以块为单位分配和回收内存。两者粒度不匹配导致**块内碎片**：一个块只要仍含有一个保留 token 就无法释放，内部空洞无法被其他请求复用。
- **量化**：作者实验显示，在 16K 上下文、多种策略和工作负载下，大部分已分配块利用率不足 50%，块内浪费（intra-block waste ratio F）达 40%–60%。此外，将 token 级策略集成到块管理运行时需要超过 500 行代码，且难以复用。
- **含义**：需要一个新的抽象层，在保留块管理效率和注意力内核兼容性的同时，支持 token 级语义，使 token 级逐出决策能真正转化为可回收的物理 KV 容量。

## 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

- **核心思想**：vToken 是一个轻量级 **token 级虚拟化层**，置于逐出策略与 PagedAttention 块管理基座之间，解耦“逻辑 token 存活”与“物理块放置”。
- **关键组件**：
  1. **Token 表（Token Table）**：每序列维护一张表，记录每个逻辑 token 的当前物理位置 `(block_id, offset)` 和存活位。提供 `evict_token(req_id, token_id)` 标记逻辑死亡、`sync_new_tokens(...)` 注册新 token、`apply_moves(...)` 原子更新重定位后的映射。策略无需感知物理块。
  2. **物理回收后端（Reclamation Backend）**：采用**惰性压缩（lazy compaction）**实现物理回收，分为四个阶段：
     - 回收资格检查：维护每块存活 token 数 n_b，计算块内浪费率 F = 1 − (Σn_i)/(N·S)。
     - 头部空间感知准入（headroom-aware admission）：仅当 F 超过阈值 θ_F（默认 0.25），且空闲块数接近低水位时，才启动回收，并从同一块预算中预留有限目的块作为工作空间。
     - 重定位规划（relocation planning）：请求本地选择低利用率源块，计算存活 token 总数 T_live，所需目的块数 ⌈T_live/S⌉，仅当释放块数大于消耗块数时采纳计划。
     - 阶段感知异步复制（stage-aware async copy）：将 KV 复制放在当前步 forward 之后的专用流上，与采样、调度等 CPU 侧工作重叠，通过 CUDA event 建立下一步 attention 之前的依赖，避免全局同步。
  3. **调度器集成**：修改 slot 映射为 `slot = token_table[token_id].block_id × S + token_table[token_id].offset`；加入调度器侧头部空间预留钩子、worker 侧回收钩子和 attention 前同步钩子；保持 CUDA Graph 兼容（仅更新可变 slot 映射缓冲区，不重捕获）。
- **正确性不变量**（4 条）：
  - I1：Token 守恒——重定位不改变逻辑身份和 KV 内容。
  - I2：唯一映射——每个活跃 token 映射到唯一位置，每个物理槽最多被一个 token 引用。
  - I3：注意力前可见性——重定位后的 KV 在复制完成前不会被 attention 读取。
  - I4：布局感知规划——计划基于一致快照，不重叠，且后置块数严格减少。

- **vToken 显著减少块内碎片**：相比 Naive-Evict，保留 KV 块每个请求减少 **27.2%–72.3%**，内存利用率平均提升约 21.7%–21.9%。
