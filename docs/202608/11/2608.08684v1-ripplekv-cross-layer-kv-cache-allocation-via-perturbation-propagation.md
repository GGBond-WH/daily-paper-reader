## 摘要
长上下文大语言模型推理受限于KV缓存内存，然而在层间分配有限的缓存预算仍然具有挑战性。现有方法依赖诸如层深度、注意力统计或表示变化等代理指标。这些代理指标并不衡量每层扰动如何传播到输出，因此可能导致敏感层分配不足，而容忍性较强的层分配过多。为解决这一问题，我们提出RippleKV，通过估计每层值缓存扰动对最终预测分布的影响来跨层分配缓存。RippleKV独立地向每层的值缓存注入范数自适应扰动，并在一个小型校准集上衡量模型输出处引起的KL散度。对这些响应取平均，得到特定于模型的敏感性分布，该分布不必随深度单调变化。随后，RippleKV通过对敏感性分数进行归一化并应用指数映射，将敏感性分布转换为层预算乘数。一个比率参数控制敏感层与容忍层之间的分配差异，而最终归一化则保持KV缓存预算。在LongBench上的实验表明，在匹配的缓存预算下，RippleKV在所评估的KV缓存压缩方法中实现了最高的平均性能。

## Abstract
Long-context LLM inference is bottlenecked by KV cache memory, yet distributing a limited cache budget across layers remains challenging. Existing methods rely on proxies such as layer depth, attention statistics, or representation change. These proxies do not measure how perturbations at each layer propagate to the output and may therefore cause sensitive layers to be underallocated while tolerant layers are overallocated. To address this issue, we propose RippleKV, which allocates cache across layers by estimating how perturbations to each layer's value cache affect the final predictive distribution. RippleKV independently injects norm-adaptive perturbations into each layer's value cache and measures the induced KL divergence at the model output over a small calibration set. Averaging these responses yields a sensitivity profile specific to the model that need not vary monotonically with depth. RippleKV then converts the sensitivity profile into layer budget multipliers by normalizing the sensitivity scores and applying an exponential mapping. A ratio parameter controls the allocation disparity between sensitive and tolerant layers, while a final normalization preserves the KV cache budget. Experiments on LongBench demonstrate that RippleKV achieves the highest average performance among the evaluated KV cache compression methods under matched cache budgets.

## 1. 核心问题与研究动机

- **背景**：长上下文大语言模型（LLM）推理场景中，KV缓存随序列长度和层数线性增长，带来严重的内存与带宽压力。KV缓存压缩成为支撑长上下文高效推理的关键技术。
- **现有方法的不足**：已有跨层缓存分配方法（如 PyramidKV、DynamicKV、CAKE 等）通常依赖**代理指标**来决定各层的缓存预算，包括：
  - 层深度（假设高层信息冗余更多，采用金字塔式递减分配）；
  - 注意力统计（如累积注意力分数）；
  - 表示变化量或中间重构误差。
- **核心问题**：这些代理指标**不直接度量"某一层缓存被压缩后，对最终预测输出产生多大影响"**。因此可能造成：
  - 敏感层（对输出影响大的层）被分配过少的缓存；
  - 容忍层（对输出影响小的层）被分配过多缓存。
- **关键实证发现**：
  - 对 Llama-3.1-8B-Instruct 的 32 层进行孤立单层压缩实验，各层的压缩损伤（KL 散度）差异高达 **17.7 倍**；
  - 最大损伤出现在**中间层**，而非浅层或深层，说明层敏感性**不随深度单调变化**；
  - 层索引与压缩损伤的平均 Spearman 相关系数仅 **0.359**，深度先验只能捕捉粗略趋势；
  - 相比之下，RippleKV 的扰动响应信号与真实压缩损伤的平均相关系数达 **0.799**（范围 0.723–0.857）。

## 2. 方法论

### 2.1 核心思想

RippleKV 的核心思想是：**通过向各层 Value 缓存注入受控扰动，并测量该扰动传播到模型最终输出分布后引起的 KL 散度，来估计各层对最终预测的敏感性，进而依据敏感性分配缓存预算。**

- 敏感层（扰动引起输出变化大）→ 分配更多缓存；
- 容忍层（扰动引起输出变化小）→ 更激进地压缩。

### 2.2 关键公式与流程

**（1）压缩损伤定义（用于分析验证，不用于实际分配）**

$$D_\ell = \frac{1}{N}\sum_{i=1}^{N} D_{KL}\left(p_i^{full}\,\lVert\, p_{i,\ell}^{comp}\right)$$

即只压缩第 ℓ 层的 KV 缓存、保持其他层不变，衡量输出分布的变化。

**（2）扰动响应定义（RippleKV 实际使用的敏感性信号）**

$$s_\ell = \frac{1}{N}\sum_{i=1}^{N} D_{KL}\left(p_i^{full}\,\lVert\, p_{i,\ell}^{pert}\right)$$

即向第 ℓ 层 Value 缓存注入扰动，保持 Key 缓存和其他层不变，测量最终输出分布的 KL 变化。

**（3）扰动注入方式（范数自适应扰动）**

$$\tilde{v}_{i,\ell,h,u} = v_{i,\ell,h,u} + \alpha\,\lVert v_{i,\ell,h,u}\rVert_2\,\epsilon_{i,\ell,h,u}, \quad \epsilon \sim \mathcal{N}(0, I)$$

- 扰动强度按每个 Value 向量的 L2 范数缩放，适应不同层/不同 token 的激活尺度差异；
- 保持 Key 缓存不变，因此注意力权重不变，仅改变聚合到的 Value 内容；
- 排除被基础压缩方法保护的 token 位置（如 attention sink 和 recent tokens）。

**（4）敏感性归一化与预算映射**

- 对敏感性分数做 min-max 归一化：
$$\hat{s}_\ell = \frac{s_\ell - s_{min}}{s_{max} - s_{min}}$$
- 通过指数映射得到预算乘数：
$$\tilde{w}_\ell = r^{\hat{s}_\ell}$$
其中 **r ≥ 1 为分配比率参数**（默认 r = 1.50），控制敏感层与容忍层之间的预算差异；r = 1 时退化为均匀分配。
- **裁剪与归一化**：将乘数裁剪到区间 [1/γ, γ]，再缩放使其均值为 1，以抑制极端分配。
- 最终层预算：
$$b_\ell = \text{round}\left(\frac{B}{|A|} \cdot w_\ell\right)$$

**（5）流程总结（Algorithm 1）**
1. 离线阶段：在小型校准集上，对模型进行完整前向获取参考输出分布；
2. 逐层扰动：每次只扰动一个层的 Value 缓存，记录输出 KL 响应；
3. 平均得到敏感性分布（模型特定、非单调、与目标预算无关，可复用）；
4. 将敏感性分布映射为层预算，推理时仅替换各层预算，保持基础方法的 token 选择策略不变。

## 6. 主要结论与发现

1. **层敏感性异质性极高且非单调**：各层压缩损伤差异达 17.7 倍，最大损伤出现在中间层，层深度不能作为可靠的分配依据。
2. **扰动响应优于深度先验**：RippleKV 的扰动响应信号与真实压缩损伤的平均 Spearman 相关性（0.799）远超层索引（0.359），说明端到端敏感性是更可靠的分配信号。
3. **RippleKV 在主实验中全面领先**：
   - Llama-3.1-8B-Instruct：10%/20%/30% 预算下平均分分别为 35.07/40.35/42.97，超过最强基线 0.83/0.42/0.71 分；
   - Qwen2.5-7B-Instruct（10%）：34.42 分，超过最强基线 0.28 分；
   - Mistral-7B-Instruct-v0.3（10%）：33.19 分，超过最强基线 0.65 分；
   - 相比 PyramidKV，RippleKV 在 Qwen 的 Multi-Document QA 类别提升了 4.80 分（20.81→25.61），在 Mistral 的 Synthetic 类别提升了 4.30 分（26.73→31.03）。
4. **效率与内存友好**：RippleKV 在 8K/128K 上下文下的延迟（6.67s/43.02s）和吞吐量（43.48/42.99 tok/s）与现有压缩方法相当甚至略优；峰值内存在 128K 时比 Full Cache 降低 31.6%，在 256K 时降低 37.8%。
5. **消融验证设计合理性**：去掉分层分配或替换为层本地信号都会导致性能下降，验证了两个核心设计缺一不可。
6. **超参数鲁棒**：R 在 1.25–1.75 之间变化时，平均分差异仅 0.41 分。

## 7. 方法优点

- **端到端敏感性度量**：直接度量"层缓存变化→最终输出分布变化"的传播效应，比层深度、注意力统计等代理信号更贴近真实压缩损伤。
- **模型特定**：敏感性分布由数据和模型共同决定，不依赖人为假设，可呈现非单调模式，适应不同架构的异质性。
- **即插即用**：仅改变各层缓存预算，保留基础方法的 token 选择策略，可与现有压缩方法无缝集成。
- **零在线开销**：敏感性 profiling 离线完成且与目标预算无关，推理时只需应用预计算的预算，不引入额外模型评估。
- **尺度不变性设计**：min-max 归一化使分配对敏感性分数的绝对尺度不敏感；范数自适应扰动降低了对激活尺度差异的敏感性。
- **形式简洁**：指数映射 + 比率参数 + 裁剪归一化，超参数少且鲁棒性好。

## 8. 不足与局限

- **校准集依赖**：敏感性分布基于小型校准集计算，校准集的规模、领域分布与目标任务的匹配程度可能影响分配质量，但论文未系统分析这一影响。
- **模型规模覆盖有限**：仅在 7B–8B 模型上验证，更大规模模型（如 70B、MoE 架构）中层间敏感性的模式是否类似尚不明确。
- **基准单一**：仅使用 LongBench，未在更多长上下文基准或真实生产负载（如多轮对话、长文档流式处理）中验证。
- **压缩比范围较窄**：实验覆盖 10%–30% 的缓存保留率，未探索更高的压缩比（如 5% 甚至更低）下的表现。
