## 摘要
大语言模型（LLM）推理服务日益受限于内存而非计算。随着长上下文和长形式推理工作负载的普及，键值（KV）缓存在LLM词元生成（即解码）期间主导了内存占用和内存流量。特别是，HBM容量已成为稀缺且昂贵的资源，严重限制了推理批次大小和系统吞吐量。本文提出OasisKV，一种以内存为中心的LLM推理系统设计，通过在LLM解码期间将完整KV缓存存储与HBM解耦，缓解HBM容量压力。由于解码时的注意力天然是稀疏的，OasisKV在HBM中仅保留最相关词元的KV条目用于注意力计算。我们观察到，使用投机解码（SD）生成的前瞻词元可以提前准确预测未来重要的词元。OasisKV采用高效的注意力后台流水线来识别重要的KV块，然后将其从更高容量的内存层级（如主机内存或远程内存）预取，并在下一步解码使用之前暂存于HBM中。我们基于vLLM实现了OasisKV。在2048词元的KV预算下，前瞻预测足够准确，可将精度保持在完全注意力的0.7个百分点以内。这使得OasisKV能够将稀疏性转化为吞吐量增益：在推理工作负载上，相比密集vLLM，吞吐量提升1.69倍，精度损失仅0.1个百分点；在多GPU长上下文服务中，吞吐量提升高达2.1倍。在预填充-解码分离架构下，OasisKV的吞吐量约为密集方案的2倍，同时每个请求的KV占用减少6.5至9.7倍，解码节点主机内存占用比完整KV传输减少2.2至2.6倍。

## Abstract
Large language model (LLM) inference serving is increasingly constrained by memory rather than compute. As long-context and long-form reasoning workloads become more prevalent, the key-value (KV) cache dominates both memory footprint and memory traffic during LLM token generation, i.e., decode. In particular, HBM capacity has become a scarce and costly resource that heavily limits inference batch size and system throughput. This paper presents OasisKV, a memory-centric LLM inference system design that alleviates HBM capacity pressure by decoupling full KV-cache storage from HBM during LLM decoding. Because decode-time attention is naturally sparse, OasisKV keeps only the KV entries of the most relevant tokens in HBMs for attention computation. We observe that future important tokens can be predicted accurately in advance using lookahead tokens drafted by speculative decoding (SD). OasisKV employs an efficient attention background pipeline to identify important KV blocks. They are then prefetched from higher-capacity memory tiers (e.g., host or remote memory) and staged in HBMs before being used in the next decode step.   We implement OasisKV based on vLLM. The lookahead prediction is accurate enough to keep accuracy within 0.7 points of full attention under a 2,048-token KV budget. This lets OasisKV turn sparsity into throughput gain: $1.69\times$ over dense vLLM on the reasoning workload at 0.1 points of accuracy loss, and up to $2.1\times$ on multi-GPU long-context serving. Under prefill--decode disaggregation, OasisKV reaches about $2\times$ dense throughput while admitting each request with $6.5$--$9.7\times$ less KV and holding $2.2$-$2.6$ less decode-node host memory than full KV transfer.

## 1. 核心问题与整体含义（研究动机与背景）

- **HBM容量与带宽成为LLM推理的主要瓶颈**：随着长上下文、Agent式工作负载（如Web-use、coding agent）兴起，KV缓存在解码阶段同时主导内存占用量与内存流量。HBM既是稀缺资源，又限制了推理批大小（batch size）与系统总吞吐。
- **现有方案各有缺陷**：
  - 稀疏注意力（如Quest、NSA）能减少KV读取，但**仍需在HBM中驻留完整KV缓存**，未解决容量问题；
  - KV检索（如ShadowKV、HiSparse）将全量KV放到CPU内存/SSD，但**按需取回位于解码关键路径上**，传输延迟直接拖慢TPOT；
  - KV预取尝试重叠传输与计算，但已有预测器要么需要训练（模型绑定），要么用当前token近似未来token、预测精度不足，且缺乏生产级跨层内存管理，难以支撑高吞吐、PD分离部署。
- **核心意义**：OasisKV将解码注意力天然稀疏性与投机解码（SD）的draft tokens结合，实现“只把下一解码步需要的KV块驻留HBM”，从而把KV缓存的容量瓶颈从昂贵HBM转移到廉价主机内存/远程内存，同时通过异步预取隐藏跨层级传输延迟，把稀疏性真正转化为吞吐量收益。

## 2. 方法论：核心思想与关键技术

### 2.1 总体架构
- 分为**计算平面**（前台forward + 后台预测/选择/预取）、**内存平面**（CPU DRAM或远程内存存全量KV，GPU HBM只持有稀疏工作集）、**控制平面**（池管理器 + 调度器）。
- 基于vLLM V1引擎实现：GPU/CPU各自维护物理KV池与页表，中间增加**head-wise逻辑到逻辑映射层**，支持不同KV头持有不同稀疏块集合。

### 2.2 前瞻注意力（Look-ahead Attention）
- **预测信号**：复用投机解码（EAGLE-3）生成的draft token，将其传播到下一解码步，作为“未来token”的查询；论文实验显示，由draft query预测的top-K集合与真实下一token查询的top-K集合一致率**平均98.74%、各层均>98.2%**，远高于用当前token作为代理（平均83.9%）。
- **全局排序**：在GPU HBM中维护每个逻辑块的压缩键摘要（Quest式逐块min/max pooling，仅占全量KV的1/16），draft query扫描摘要即可对所有历史块排序，无需恢复完整KV。
- **低开销前台**：一次前向传播同时处理normal query和draft query（合并为stacked queries），共享权重与驻留KV读取开销。

### 2.3 完全异步后台流水线
- 每层形成“top-K预测 → KV选择 → KV传输”三级流水，不同层间任务相互独立，分别在独立CUDA stream上运行持久后台worker；CUDA event维持层内依赖。
- 前台在**每层开始注意力前只等待该层**上一解码步发出的传输完成，而非等待所有层；流水线稳态节拍满足：
  - \(T_{pipe} = \max\{T_{pred}, T_{select}, T_{transfer}\} \le \Delta_{prefetch} = T_{step} / N_{layer}\)

### 2.4 Delta选择与有上限驱逐（Capped Eviction）
- 选择阶段先求预测集与驻留集的交集（已驻留块不产生PCIe流量），再按“最近最少被选中”（LRU）选择驱逐目标，将缺失块与驱逐目标配对组成传输计划。
- 每头每步最多传输 \(C\) 个块（由fetch ratio控制），从而将每步跨PCIe传输量限制在解码时间预算 \(C_{token} = B_{link} \cdot T_{decode}\) 之内。

### 2.5 远程部分取回（Remote Partial Fetching, RPF）
- **PD分离场景**下不在接入时传输全量KV：
  - **部分传输（admission）**：prefill节点多算一步解码，得到首个生成token的query，选出每层top-K块并取并集，只传输该并集（+压缩键摘要 + draft KV状态），prefill GPU可提前释放；
  - **网络预取（decode）**：解码过程中若top-K集合漂移到本地没有的块，后台流水线从prefill节点主机内存经网络拉取到decode节点主机DRAM，再gather进GPU HBM；跨请求同层缺失会聚合传输。
- 效果：每个块至多跨网传输一次，从未被选中的块永不传输；请求KV从“一次性全量突发传输”变成“随解码分布式按需填充”。

## 3. 实验设计

### 3.1 模型与数据集
- **模型**：Qwen3-8B（dense）、Qwen3-235B-A22B（MoE）、Llama-3.1-8B-Instruct；draft模型用对应公开EAGLE-3 head。
- **精度基准**：AIME24/AIME25（数学推理）、GPQA-Diamond（科学推理）、LongBench v2（长上下文理解，分short/medium/long三个子集）。
- **性能基准**：合成解码扫描（16K/32K上下文、最大并发8–256、每请求生成2048 token）、真实AIME24端到端工作负载、PD分离场景（24K/32K上下文、offered rate扫描、192请求）。

### 3.2 对比方法
- **性能**：dense vLLM（FlashAttention-3全KV驻留）、ShadowKV、InfiniGen、FreeKV（各自框架运行）。
- **精度**：全注意力锚点（各框架自己的）、Quest、FreeKV；三者均在相同2,048-token KV预算下比较，且只与**同栈**全注意力比较差值。
- **默认配置**：块大小16，K=128块/头（=2048 token），加活跃局部块共129块；压缩键缓存为全量KV的1/16；无sink token、无dense层。

### 3.3 关键实验结果
- **单/多GPU**：Qwen3-8B单H100在16K下吞吐最高2.1×（1,398 vs 676 tok/s）；Qwen3-235B TP8最高1.9×（1,102 tok/s）；并发16时同时改善TPOT与吞吐。
- **PD分离**：吞吐为dense的2.1–2.3×；每请求KV传输减少6.5×（24K）和9.7×（32K）；decode节点主机内存占用降低2.2×（24K）和2.6×（32K）。
- **真实推理负载**：Qwen3-8B AIME24吞吐1.69×（2,083 vs 1,235 tok/s），精度仅-0.1；Qwen3-235B 1.20×（1,546 vs 1,283），精度-0.84。
- **精度**：统一2,048-token预算下，相对全注意力损失<0.7点；LongBench整体-0.4/-0.6，AIME24/25 pass@8与全注意力持平，avg@8分别-2.5/+2.55，GPQA-Diamond pass@4仅-1.99。
- **消融**：
  - **fetch ratio**：0.01→fetch all使吞吐从2,178跌至824 tok/s（2.6×变化），精度仅从74.9到77.4波动；最佳操作点为0.05（精度75.94 vs dense 76.04，吞吐2,083）。
  - **top-K预算**：K从192降到64，Qwen3-8B加速从1.39×升到1.89×，精度降4.4点；K≥128时精度平稳。
  - **RPF网络流量**：fetch ratio 0.05时总KV传输比全量减少2.2×（32K），网络带宽分布更均匀，链路空闲时间从60%降至1–2%。

## 6. 主要结论与发现

- **前瞻token能准确预测解码注意力模式**：EAGLE-3 draft query预测的top-K块与真实下一token查询高度一致，精度足够支撑稀疏预取。
- **稀疏预取可将记忆瓶颈转化为吞吐收益**：在2,048-token KV预算下，精度损失<0.7点，但可换取推理场景1.69×、多GPU长上下文2.1×、PD分离2.1–2.3×的吞吐提升。
- **每步传输量是核心约束**：吞吐受PCIe/网络带宽而非注意力计算限制；通过fetch cap把每步传输约束在解码时间窗口内，能实现“低精度损失+高吞吐”的最优操作点（0.05）。
- **PD分离下无需全量KV落地**：RPF可把每请求KV传输减少6.5–9.7×、decode节点DRAM占用减少2.2–2.6×，并将网络流量从突发型变为均匀型，且在高prefix-cache命中率下显著降低TTFT。

## 7. 优点

- **训练无关、通用性强**：仅复用投机解码已产出的draft token，无需训练/微调专用预测模块，可直接部署于现有SD链路。
- **生产级系统设计**：构建于vLLM之上，支持多GPU张量并行、PD分离、CPU/GPU分页与统一的head-wise映射，兼容FlashAttention类内核路径。
- **精度/吞吐权衡清晰**：通过fetch ratio和top-K预算提供显式控制旋钮，且实验显示精度对旋钮不敏感、吞吐对旋钮高度敏感，便于实际部署

- **兼容性强、部署成本低**：构建于 vLLM 之上并复用投机解码链路，而非从零实现推理框架；新增的页表映射层与后台 worker 对上层 API 透明，容易在生产栈中集成。
- **实验严谨**：在精度评估中明确采用“同框架全注意力锚点差值”的协议，避免不同框架间绝对分数不可比的陷阱；同时报告平均差值与 pass@k 等多维度指标，结论可信度高。

## 8. 局限性

- **依赖 draft 模型质量**：前瞻预测完全建立在 EAGLE-3 类 draft 模型已部署的前提上，若 draft 质量下降（如领域漂移、长尾 token），其 top-K 与真实查询的 98% 一致率可能显著恶化，进而破坏预取命中率。
- **评估语境仍偏“中等长度”**：LongBench v2 的 long 子集虽覆盖 32K–128K 上下文，但论文没有验证百万级 token 或 infinite-context 场景下块漂移率与远端内存带宽的交互；极长上下文中重复模式与罕见模式的分布差异可能改变最优 fetch ratio。
- **未纳入量化等正交优化**：KV 缓存做 8-bit/4-bit 压缩、非均匀块大小、动态 top-K 均可能进一步降低体量或提升命中率，但这些与 OasisKV 的收益是加法还是乘法尚未探索。
- **图 11 对比不完整**：多个基线在部分高并发配置下无法运行，导致最激烈竞争区（高 batch、长上下文）缺少直接对照数据；真实负载仅测 AIME24，未覆盖 agentic、多轮工具调用场景。
- **强制拒绝 draft token**：当前实现只取 draft 的 query 作为预测信号而丢弃其生成 token，实际等于放弃了一部分投机解码可带来的延迟收益；若与“采纳 draft”联合，吞吐提升可能有上限，需要更复杂的时序协调。
- **硬件平台单一**：结论建立在 H100（HBM3 80GB，PCIe Gen5）与 400G RoCE 之上；在 H200/Blackwell 等 HBM 带宽大幅提升、或异构 CXL 内存系统中，跨层带宽与容量的最优均衡点会平移，需要重新标定控制参数。
- **未显式讨论长尾局部性极端情况**：如检索型任务中极少数历史位置被反复高频访问、而多数位置几乎不被访问时，LRU 驱逐与 top-K 固定预算的交互可能会造成抖动，论文未给出此类压力测试。

## 9. 对领域与未来研究的启示

- **“预测未来 token”是比“用当前 token 近似”强得多的稀疏性信号**：该结论本身具有独立价值，可迁移到 MoE 专家预取、激活 offload 调度乃至长程记忆机制设计。
- **把 KV 的主存储位置从 HBM 移到 CPU DRAM/远程内存是可行且高效的**：在每步解码时间窗口内做有上限的跨层传输，既绕开容量瓶颈又不至于让延迟暴露在关键路径上；这为 NVMe SSD 或 CXL 内存等更慢但更便宜的层级打开了空间，“带宽预算 × 解码步时”的建模方法可作为通用设计范式。
- **PD 分离不应默认“全量接引”**：RPF 揭示出一个更优的接引策略——只迁移首个 token 对应的 top-K 子集，其余随解码按需异步拉取，且每块至多线上传输一次；这一思路对 Cache 一体化调度、prefix-aware admission、网络突发削峰都有直接参考价值。
- **跨层内存管理的系统抽象值得推广**：论文提出的 head-wise 逻辑到逻辑映射层、GPU/CPU 双侧页表、后台持久 worker 与 CUDA event 依赖流水线，可作为统一稀疏推理框架的参考设计，特别是其“前台只等在用层、层间全异步”的流水节拍分析具有理论指导意义。
- **端到端联合优化是下一个可能的方向**：将前瞻预取与投机解码采纳、prefix caching、连续批处理、网络聚合传输（跨请求同层合并）统一进一个控制器，在全局能量与延迟约束下动态决定 fetch ratio 与 top-K，是后续最有潜力的工作。

## 10. 总结

OasisKV 针对 LLM 解码阶段 KV 缓存同时主导容量与带宽、而现有稀疏方法与 KV 检索方案分别受制于 HBM 容量与传输延迟这两个矛盾，提出了一套训练无关、可部署于生产推理栈的解决方案：利用投机解码产生的 draft token 作为未来 token 的忠实替身，以极高精度预测“下一解码步将读取哪些 KV 块”；配合 HBM 内压缩键摘要进行全局 top-K 排序，再以完全异步的后台流水线（预测—选择—传输）将缺失块在每步解码时间窗内从 CPU DRAM 或远端节点预取回 HBM。系统还通过 delta 选择、有上限驱逐与远程部分取回（RPF），将跨 PCIe/网络传输量严格约束在内存带宽预算之内，并在 PD 分离场景中避免全量 KV 落地传输。实验表明，在 2,048 token 的稀疏预算下精度损失小于 0.7 点，同时单 GPU 吞吐提升最高 2.1×、多 GPU 达 1.9×、PD 分离达 2.1–2.3×，每请求 KV 传输量减少 6.5–9.7×。它证明了“稀疏性可被系统化地转化为吞吐收益”这一核心命题，也为后 HBM 时代的大模型推理内存层级设计提供了一个务实且完备的参考实现。
