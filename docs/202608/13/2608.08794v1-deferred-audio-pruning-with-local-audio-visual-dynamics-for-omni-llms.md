## 摘要
全模态大语言模型联合处理音频、视频和文本，但长多模态序列会带来大量的预填充和KV缓存开销。现有的全模态压缩方法主要关注大语言模型前的令牌缩减，而跨大语言模型边界的模态特定压缩尚未得到充分探索。我们提出了A-PACK，一个两阶段框架，将音频剪枝推迟到查询条件下的多模态交互出现之后。我们的分析表明，与视频相比，音频在每令牌上具有更高的任务相关信息密度和表示多样性。我们进一步发现，局部音视频动态为视觉选择提供了比逐令牌匹配更有效的线索。因此，我们在进入大语言模型之前保留音频并使用局部动态压缩视频，然后在大语言模型内部逐步剪枝低相关性的音频和视觉令牌及其KV缓存条目。在Qwen2.5-Omni-7B/3B的四个基准测试上，A-PACK在所评估的既有方法中取得了最强的平均性能，同时将预填充FLOPs减少高达78%，并将解码吞吐量提升高达2.21倍。

## Abstract
Omni-modal LLMs jointly process audio, video, and text, but long multimodal sequences incur substantial prefill and KV-cache costs. Existing omni-modal compression methods primarily focus on pre-LLM token reduction, leaving modality-specific compression across the LLM boundary underexplored. We propose A-PACK, a two-stage framework that defers audio pruning until query-conditioned multimodal interactions emerge. Our analysis shows that audio exhibits higher task-relevant information density and representational diversity per token than video. We further find that local audio-visual dynamics provide a more effective cue for visual selection than token-wise matching. We therefore preserve audio and compress video with local dynamics before the LLM, then progressively prune low-relevance audio and visual tokens and their KV-cache entries inside the LLM. Across four benchmarks on Qwen2.5-Omni-7B/3B, A-PACK achieves the strongest average performance among the evaluated prior methods while reducing prefill FLOPs by up to 78% and improving decoding throughput by up to 2.21x.

## 1. 核心问题与整体含义（研究动机与背景）

全模态大语言模型（Omni-LLM）能够联合处理音频、视频和文本，但长多模态序列会带来两个严重瓶颈：**prefill 计算量**和 **KV-cache 内存/解码开销**。现有全模态压缩方法高度集中于"进入 LLM 之前"的 token 剪枝：

- **早剪枝的风险**：在音频、视频和查询尚未在 LLM 内部形成联合上下文之前，模态表示仍是各自独立的，此时的相关性估计不完整，容易误删短暂但关键的音频证据（如喊声、笑声等）。
- **点对匹配的不足**：token 级的音频–视觉相似度匹配（如 OmniZip 等）可能将时间上相隔甚远但语义相似的事件错误关联，忽略了时间局部性。

论文据此提出一个核心观点：**token 相关性的判断标准在 LLM 边界前后应不同**。

- LLM 之前：音频在每个 token 上承载更密集、更精炼的证据，应保留；视频冗余度高，可激进压缩。
- LLM 之后：联合上下文已形成，可基于查询条件可靠地评估并剪除低相关性的音频和视觉 token。

作者提出 **A-PACK（Audio-Prioritized Allocation with Context-aware KV-Cache Pruning）**，一个两阶段框架：先在 LLM 前保留音频、用局部音视频动态结构指导视频压缩；再在 LLM 内部基于查询注意力渐进式剪除低相关性的多模态 token 及其 KV-cache 条目。

## 2. 方法论

### 2.1 核心思想

将全模态 token 压缩视为一个"**跨 LLM 边界、且随模态和阶段自适应**"的问题。不同于现有方法在 LLM 之前做一步到位的模态决策，A-PACK 把压缩划分为两个阶段，并赋予不同原则：

| 阶段 | 模态处理 | 压缩依据 |
|------|----------|----------|
| 阶段一（pre-LLM） | 保留全部音频；仅压缩视频 | 查询粗相关性 + 局部音频–视觉动态结构（CKA）+ 视频内部冗余去除 |
| 阶段二（inner-LLM） | 同时剪除低相关音频和视觉 token | 查询条件化的注意力分数（query–key attention） |

### 2.2 关键技术细节

**阶段一：Pre-LLM 局部对齐压缩**

- **对齐分数（CKA）**：使用带时间窗口的 **CKA（Centered Kernel Alignment）** 度量局部音频–视觉协变结构。窗口 w=3，线性 CKA 公式如下：
  ```
  c_f = ||V_f^T A_f||_F² / (||A_f^T A_f||_F · ||V_f^T V_f||_F)
  ```
  CKA 的优势：对称、保留结构信息、避免最优传输的质量约束和 Sinkhorn 开销。

- **门控细粒度分数**：当片段平均 CKA（¯c）低于阈值 τ=0.78 时，用逐帧音频–视觉距离 1−d̂_f 作为补充，以捕捉时间偏移后的对应关系：
  ```
  s_f = c_f（¯c ≥ τ）
  s_f = (1−β)·c_f + β·(1−d̂_f)（¯c < τ）
  ```
  β=0.90。

- **分段与预算分配**：按连续帧余弦相似度（τ_sim=0.97）切分场景段，按段重要性分配视觉预算。段分数公式为：
  ```
  g_m = √|G_m| · [λ·max(r_f) + (1−λ)·mean(r_f)]
  ```
  其中 r_f 为帧查询相关性，λ 平衡峰值与持续相关性。

- **锚点 token 选择（去冗余）**：第一帧作为锚点，用 **DA-FPS（密度感知最远点采样）** 选取高覆盖代表 token；非锚点帧保留与锚点在相同空间位置上最不相似的 token，以保留新出现的证据。

**阶段二：Inner-LLM 查询感知压缩**

- 从中层解码器开始（7B 为第 14 层，3B 为第 18 层），逐步按查询注意力分数剪枝。
- 注意力分数公式：
  ```
  I_i = exp(q^T k_i / √d) / Σ_j exp(q^T k_j / √d)
  ```
  多头上平均，无需额外前向开销（查询–键交互已被解码器计算）。
- 每层保留 Top-(1−P) 比例的 token，并同步删除其 KV-cache 条目。P=10%（35% 层级）/15%（25% 层级）。

### 2.3 算法流程（Algorithm 1 概要）

1. 将音频嵌入重采样到视觉帧时间轴并均值池化；
2. 平滑后按连续帧余弦 < τ_sim 切分片段；
3. 按帧–查询相关性和局部 CKA 计算各帧视觉基础分；
4. 按片段的查询相关性和 CKA 分数分配视频预算；
5. 锚点帧用 DA-FPS 选 token，非锚点帧去冗余；
6. 将保留的音频 + 视频 token 送入 LLM；
7. 从 L_mid 层开始，每层按查询注意力保留 Top-(1−P)，剪除其余 token 并裁剪 KV-cache 条目。

## 5. 主要结论与发现

1. **音频每 token 效用更高**：音频 token 的任务相关信息密度是视频的 9.8 倍，表示多样性（有效秩）高 1.7 倍。固定预算下保留音频始终优于剪除音频（AVUT +5.1，WorldSense +1.8）。
2. **局部动态优于点对匹配**：局部窗口 CKA 比静态余弦匹配更能反映真实的音视频共现；在 WorldSense 全部 8 个领域上优于静态余弦，配对检验显著（p=0.0117）。
3. **跨边界的延迟剪枝有效**：A-PACK 在 35% 层级保留 Full Tokens 平均准确率的 98.8%（7B），25% 层级保留 97.0%，同时将最终 token 保留率压缩至 5.6%。
4. **两阶段互补**：pre-LLM 阶段贡献大部分准确率提升，inner-LLM 阶段在保持准确率的同时大幅降低后续计算和 KV-cache 成本（44.6% → 29.9% prefill FLOPs）。
5. **稳定性随保留比例良好**：最终保留 15%/25%/35% 时准确率变化不超过 0.4 分，说明渐进式剪枝对保留目标不敏感。

| **公平评价** | 按实际 prefill FLOPs 匹配各方法工作点，而非名义 token 保留率，评价协议严谨 |
| **消融完整** | 覆盖阶段组合、预对齐评分函数、超参数敏感性、token 预算、定性案例等，从多个角度验证了设计决策 |
| **效率可视化** | TTFT 分解图清楚展示了各方法的时间花在哪（视觉塔、预处理、LLM 骨干），并能解释方法的瓶颈所在 |
| **代码开源承诺** | 论文声明接受后发布代码，便于复现 |

## 7. 不足与局限

### 7.1 论文自述的局限

- **细粒度时间定位不足**：定性失败案例中，A-PACK 保留了相关音频和视觉线索，但无法精确到秒级（将"0:05–0:07"答为"0:09–0:11"），说明局部窗口覆盖了事件邻域但未保护精确的声学转移。
- **音频保留策略不普适**：虽在 Qwen2.5-Omni 上最优，但跨模型/任务时音频优先级可能不恒定，需要自适应调节。
- **局部协变对时间偏移敏感**：当音视频事件存在系统性时间滞后时，CKA 信号可能减弱。

### 7.2 可关注的其他局限

- **骨干单一**：所有实验仅在 Qwen2.5-Omni（7B/3B）上验证，未覆盖其他 Omni-LLM 架构（如 Baichuan-Omni、Ola 等），泛化性待验证。
- **无训练扩展**：训练无关是优点也是限制——若允许微调，剪枝与模型表示可以更好配合，但文中未探索训练增强的路径。
- **视频模态信息丢失风险**：25% 层级下最终仅保留 5.6% 的 token，虽平均性能保留 97%，但对长尾/细节型任务（如精确计数、细粒度事件定位）可能不利。
- **定量成本口径**：FLOPs 按解析公式估算（基于 token 数和层数），未报告真实 GPU 峰值算力利用率，可能与实际墙面时钟存在偏差。
- **幻觉基准覆盖较窄**：AVHBench 用于评估对齐评分消融，但未进入主结果平均，且仅用了准确率/F1 指标，未做更深入的错误类型分析。
- **未报告推理总能耗**：内存降低了 2.3 GB，但未量化功耗或更全面的部署成本。

## 8. 总结性评价

A-PACK 是一项**问题意识敏锐、方法论完整、实验验证扎实**的效率优化工作。其核心贡献在于将全模态压缩从"LLM 前的一次性选择"扩展为"跨 LLM 边界、随模态和阶段自适应"的渐进过程，并以量化证据（信息密度、有效秩、局部 CKA）支撑每个设计决策。在当前长上下文多模态推理成本高企的背景下，该工作具有较强的实际部署价值，也为后续 Omni-LLM 的高效化研究提供了"何时压缩、压缩什么、依据什么"的通用分析框架。
