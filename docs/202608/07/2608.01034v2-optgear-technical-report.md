## 摘要
我们介绍了OptGear，这是一个为高效设备端部署、实时推理和强大任务能力而设计的基础模型。它包括一个密集模型（1M、270M和1B），上下文长度为64K。我们设计了一种新的混合架构，将卷积键值门控混合器与局部-全局注意力相结合，以减少随着长上下文而呈指数级增长的KV缓存内存。与类似规模的模型相比，该架构在NPU上的预填充和解码速度提高了X4.9倍。从2T tokens的候选语料库中，OptGear在一个精选的0.5T tokens子集上训练，无需知识蒸馏。这是现有基础模型中数据效率最高的。所有模型均以开放权重和ONNX、Qualcomm NPU及Apple ANE的部署二进制文件发布，使OptGear成为需要快速、内存高效推理和强大任务能力的边缘应用的实用基础。此外，为了扩展设备端生成语言模型的生态系统，我们推出了OptGear-1M，可部署在微控制器单元（MCU）上，这是一种微型语言模型（TLM）。OptGear-1M是首个在STM32H747I-DISCO的ARM Cortex-M7 CPU上通过W4A32量化实现20 TPS的生成语言模型。

## Abstract
We introduce OptGear, a foundation model designed for efficient on-device deployment, real-tim inference, and strong task capability. It includes a dense model (1M, 270M, and 1B) with a context length of 64K. We designed a new hybrid architecture that combines a convolutional key-value gated mixer with local-global attention to reduce the KV-cache memory that tends to increase exponentially with long context. This architecture delivers up to X4.9 faster prefill and decoding speeds on the NPUs compared to models of a similar scale models. From a 2T tokens candidate corpus, OptGear is trained on a curated 0.5T tokens subset without knowledge distillation. This is the most data-efficient of the existing foundation models. All models are released with open weights and deployment binaries for ONNX, Qualcomm NPU, and Apple ANE making OptGear a practical base for edge applications that need fast, memory-efficient inference and strong task capabilities. Furthermore, to expand the ecosystem of on-device generative language models, we are introducing the OptGear-1M that can be deployed on Micro-Controller Units (MCUs), a Tiny Language Model (TLM). OptGear-1M is the first generative language model to achieve 20 TPS with W4A32 quantization on the ARM Cortex-M7 CPU of the STM32H747I-DISCO.

## 1. 核心问题与整体含义（研究动机和背景）
- **端侧部署挑战**：在智能手机、平板、汽车、机器人、嵌入式设备上运行 LLM 可带来低延迟、隐私保护、离线可用等优势，但设备受限于 SRAM 容量、功耗、实时性和异构 SoC（CPU/GPU/NPU）资源。
- **现有模型不适配**：当前主流开源模型（如 Llama、Gemma 等）主要为服务器级 GPU 设计，依赖高带宽内存和强大算力，难以直接部署到边缘设备。
- **关键技术瓶颈**：Grouped-Query Attention（GQA）在长上下文下复杂度为 O(N²)，且自回归解码需要反复访问 KV-cache，导致内存占用和带宽需求随上下文长度线性增长，成为移动 NPU/GPU 上延迟和功耗的主要瓶颈。
- **论文目标**：提出 Opt.Gear，一个面向端侧部署的生成语言模型家族，通过联合优化下游质量、设备端延迟、内存效率、长上下文能力和硬件可部署性，解决上述问题。

## 2. 论文提出的方法论（核心思想、关键技术细节、公式或算法流程）
- **总体架构**：混合序列混合架构，结合全局注意力（GQA）、局部注意力（滑窗注意力）和 ConvKV-Gated Mixer 三种路径。
- **ConvKV-Gated Mixer（核心创新）**：
  - 对输入序列 X，首先将每个 token 投影为 query、key、value：  
    \(q_t = x_t W_q,\; k_t = x_t W_k,\; v_t = x_t W_v\)
  - 对 key 和 value 分别做因果深度可分离 1D 卷积：  
    \(\tilde{k}_t = \sum_{i=0}^{L_{conv}-1} a_i \odot k_{t-i},\; \tilde{v}_t = \sum_{i=0}^{L_{conv}-1} b_i \odot v_{t-i}\)
  - 通过 sigmoid 门控融合：  
    \(g_t = \sigma(q_t \odot \tilde{k}_t),\; y_t = g_t \odot \tilde{v}_t,\; o_t = y_t W_o\)
  - 该模块不构建逐 token 注意力矩阵、不进行 softmax，仅使用静态线性、卷积和逐元素操作，更易映射到边缘运行时。
- **内存高效缓存机制**：
  - 全局 GQA 缓存规模：\(O(2 C d_{kv})\)；局部滑窗注意力缓存：\(O(2 W d_{kv})\)
  - ConvKV-Gated Mixer 仅保存固定大小的卷积状态：\(\mathcal{C}_K, \mathcal{C}_V \in \mathbb{R}^{d_{kv} \times L_{conv}}\)，缓存规模为 \(O(2 L_{conv} d_{kv})\)，与上下文长度无关。
  - 预填充后仅需保留最后 \(L_{conv}\) 个投影状态，解码时追加当前 token、丢弃最旧项、执行缓存上的卷积即可。
- **模型配置**：
  - 三个尺寸：Opt.Gear-1B、270M、1M
  - 共享混合架构：GQA + 局部注意力 + ConvKV-Gated Mixer；QK-LN 归一化
  - 1B/270M：head dim 256，滑窗 512，卷积核 size 3，RoPE 全局 theta 1,000,000 / 局部 theta 10,000，上下文 64K
  - 1M：面向 MCU，隐藏维 128，5 层，2 query head / 1 KV head，卷积核 size 4，上下文 512，自定义 2,048 BPE 词表
- **量化感知训练（QAT）**：
  - 初始化：基于 GPTQ 的逐层输出重构目标，用校准激活估计层敏感度，选择使量化误差最小的 scale（Hessian 感知初始化）
  - 微调：采用 LSQ（Learned Step Size Quantization），将每组 scale 作为可学习参数，并使用直通估计器处理舍入不可导问题
  - 保证初始化、QAT 和部署时使用相同的 INT4 group 网格，避免量化器不匹配

- **量化训练方法严谨**：从 GPTQ 初始化到 LSQ 微调，全程保证 INT4 group 网格一致，避免了初始化、QAT 与部署时量化器不匹配的常见工程陷阱；同时验证了 QAT 后叠加 PTQ（如 AWQ/GPTQ）的鲁棒性，展现出较强的抗量化退化能力

- **数据混合策略缺乏敏感性分析**：6% 韩语、2% 数学的比例是经验选择，未报告不同混合比例对下游指标的影响，缺少消融实验支撑，读者难以判断最优性
- **长上下文评估不充分**：宣称支持 64K 上下文，但主要评估集中于短上下文基准（MMLU、HellaSwag 等），没有在 RULER、LongBench 或大海捞针等长上下文专门基准上提供系统性评测；实际外推能力存疑

## 9. 个人思考与启示
- **架构设计的启示**：Opt.Gear 的核心贡献在于将“硬件可映射性”作为第一性约束（算子全部为静态线性、卷积和逐元素操作，避免动态 shape 和注意力矩阵），再通过混合注意力维持模型质量。这为端侧 LLM 设计提供了一个重要思路——性能优先、通过架构设计解决推理瓶颈，而不是依赖运行时优化
- **数据效率的启示**：在 0.5T token 且无知识蒸馏的情况下超越多个大 token 数模型，表明小型化模型在数据质量、任务覆盖和训练策略上的精心设计，可以部分弥补参数规模和数据量的不足；同时也暗示“大数据 + 大模型”的规模化法则并不完全适用于极致边缘场景
- **量化的工程价值**：论文将量化视为部署 pipeline 的组成部分（初始化 → QAT → 部署），而非后处理步骤，这一流程对工业界落地具有直接参考价值
- **仍需回答的问题**：ConvKV-Gated Mixer 成功是否依赖特定数据分布（如韩语、数学）？全局+滑窗+卷积的混合比例（各占多少层）是否有更优配置？在更长上下文（128K/256K）下卷积状态是否会成为信息瓶颈？这些问题值得后续工作深入探讨


### 总结一句话
Opt.Gear 是一次将硬件感知设计、混合注意力架构、数据效率训练和全栈部署（MCU → CPU/GPU/NPU）系统性地整合起来的端侧 LLM 实践，在推理速度、量化鲁棒性和小模型数据效率方面取得了显著成果，但其对比公平性、长上下文评估和硬件资源配置方面的不足也提醒读者需谨慎看待部分性能优势。
