## 摘要
将大语言模型（LLM）推理的预填充和解码阶段分离到两组不同的节点上，是当今LLM服务系统中广泛采用的做法。然而，这种架构对在租用云实例上自托管LLM部署提出了重大挑战，因为在分离节点之间传输大量键值（KV）缓存很容易使有限的节点间网络带宽饱和。在本文中，我们提出通过选择性跨阶段传输关键KV缓存条目来缓解网络瓶颈。实现选择性KV缓存传输面临两个挑战，即预填充阶段的准确KV选择和解码阶段的高效KV获取。为解决这些挑战，我们设计了SmartGen，一个KV缓存传输引擎，通过三条数据传输路径实现无缝的分离式LLM推理。具体而言，我们利用：1）基于配置文件的主动传输路径，在预填充阶段识别并将关键KV缓存条目推送到解码节点；2）并行按需传输路径，在解码阶段同时获取远程和本地KV缓存条目；3）推测性传输路径，最终将所有KV缓存传送到解码节点。实验结果表明，与典型的全量KV缓存传输方法相比，SmartGen将首次输出令牌时间（time-to-second-token）最多降低4.3倍，同时提供可比的后续解码性能和准确性。

## Abstract
Disaggregating the prefill and decoding stages of large language model (LLM) inference into two separate sets of nodes is widely adopted in today's LLM serving systems. However, such an architecture poses significant challenges for self-hosted LLM deployments on rented cloud instances, since transferring enormous key-value (KV) caches between disaggregated nodes can easily saturate the limited inter-node network bandwidth. In this paper, we propose to mitigate the network bottleneck by selectively transferring essential KV cache entries across the two stages. There are two challenges to achieve selective KV cache transfer, i.e., accurate KV selection during the prefill stage, and efficient KV fetching during the decoding stage. To address these challenges, we design SmartGen, a KV cache transfer engine that allows seamless disaggregated LLM inference with three data transfer paths. Specifically, we leverage 1) a profile-based proactive transfer path to identify and push essential KV cache entries to the decoding node during the prefill stage, 2) a parallel on-demand transfer path to simultaneously fetch remote and local KV cache entries during the decoding stage, and 3) a speculative transfer path to finally deliver all KV caches to the decoding node. Experimental results show that SmartGen reduces time-to-second-token by up to 4.3x compared with the typical full KV cache transfer approach while offering comparable subsequent decoding performance and accuracy.

## 1. 核心问题与研究动机

**背景与问题：**
- 大语言模型（LLM）推理分为**预填充（prefill）**和**解码（decoding）**两个阶段，业界广泛采用**P/D分离架构**（如 Mooncake、Splitwise、DistServe 等），将两阶段部署到不同节点上以独立扩缩容。
- 然而，对于在**租用云实例**上自托管 LLM 服务的用户，分离式架构面临严重瓶颈：预填充节点必须将大量 **KV Cache** 传输给解码节点，而云实例的节点间网络带宽通常仅有 10–35 Gbps。
- 实验数据显示：在 L20 GPU、25 Gbps RDMA 网络上处理 48K token 的长提示词时，**KV 缓存传输耗时是预填充计算的 6.5 倍**；KV 传输可占作业完成时间的 **42.2%**。
- 现有系统（Splitwise、DéjàVu 等）试图通过将传输与预填充计算**重叠（overlap）**来隐藏延迟，但作者实验发现：随着模型规模、序列长度和批处理大小增长，传输延迟远超预填充计算（差距最高可达 7.1 倍），**重叠策略无法从根本上解决带宽瓶颈**。作者将这一问题称为 **"阶段转换停滞"（stage-transition stall）**，其直接影响用户体验指标 **TTST（time-to-second-token，第二个词元到达时间）**。

**核心洞察：**
- KV Cache 存在**动态稀疏性**——并非所有 KV 条目在解码阶段都是必需的，现有稀疏注意力算法（InfiniGen、HATA 等）已证明只选择少量关键条目即可保持模型精度。
- 若能将该稀疏性应用于**传输阶段**，则只需传输少量重要 KV 条目即可显著缓解网络瓶颈。

## 2. 方法论：SmartGen 设计

### 核心思想

SmartGen 将 KV 条目划分为三类，并设计三条对应的数据传输路径：

| KV 条目类别 | 特征 | 对应传输路径 |
|---|---|---|
| **通用重要（universally important）** | 与具体提示词无关、位置稳定的重要条目 | **Profile 驱动的主动传输**（§4.1） |
| **上下文相关（context-dependent）** | 对特定查询才重要的条目 | **并行按需传输**（§4.2） |
| **次要重要（less important）** | 剩余条目 | **推测式传输**（§4.3） |

### 关键技术细节

#### (1) Profile-based 主动传输（§4.1）
- **关键发现——位置相似性**：通过对多种模型和数据集的分析（图 5），发现重要 KV 条目在序列中的相对位置分布具有一致性，不随数据集和提示词长度变化。例如 Qwen3-14B 第 8 层中，最后 25% 的 token 被超过 30% 的注意力头和请求选中。
- **离线 KV 选择**：基于校准数据集运行一次推理，统计每个 KV 条目的被选频率 S(e)，按块计算重要性：
  - 公式：$I_{l,m} = \begin{cases} \infty, & \text{if } l = 0 \text{ or } 1 \\ \frac{1}{|E(B_{l,m})|} \sum_{e \in E(B_{l,m})} S(e), & \text{if } 2 \le l < L \end{cases}$
  - 前两层注意力（l=0,1）始终被选中。
  - 可预传输的 KV 块数：$K_r = M \cdot (L-1) \cdot T_p / T_t$，其中 $T_p$ 为预填充时间，$T_t$ 为全量传输时间（取前 L−1 层预填充时长作为可重叠上界）。
- **在线 KV 传输**：预填充阶段每层 KV 缓存卸载到 CPU 内存后，按 M=1K 个 token 分块，若块位置属于 top-Kr 重要块，则通过 **RDMA WRITE** 单边推送至解码节点；同时用门铃批处理（doorbell batching）附带更新 KV mask。

#### (2) 并行按需传输（§4.2）
- **目标**：消除解码阶段远程 KV 获取的网络往返（round-trip）在关键路径上的开销。
- **双通道（two-lane）KV 获取**：将 KV index 拆分为本地索引和远程索引，本地 KV 从主机内存加载的同时，远程 KV 通过 RPC 从预填充节点获取，两者并行执行。
- **基于掩码的索引拆分（Mask-based Index Splitting）**：
  - 为每层维护一个 int8 的 **KV mask 矩阵**（形状 B×N，内存开销极小，64K token 时仅 2.5 MB）。
  - mask 值含义：0=填充 token（跳过）、1=本地可用、2=位于远程预填充节点。
  - 利用 RDMA 的**保序性**（in-order delivery），先写 KV 块、再更新 mask，保证一致性。
  - 通过 GPU 上的轻量索引操作（Algorithm 1）将生成的 KV index 拆分为 local_index 和 remote_index。
- **基于重排序的 KV 汇聚（Reordering-based KV Gathering）**：
  - 利用**注意力计算对 KV 条目顺序不敏感**（softmax(QK^T/√d)V 中 KV 已含位置信息），将每行 KV 条目按 mask 值降序排序，使远程条目在行内连续，便于 RDMA NIC 批量接收。
  - 利用 RDMA NIC 的**散射-汇聚（scatter-gather）DMA 能力**（上限约 20 个段），将连续接收的 KV 条目直接分散写入 GPU 内存的正确位置，避免解码节点额外启动 scatter kernel。

#### (3) 推测式传输（§4.3）
- **动机**：并行按需传输仍难以完全隐藏网络开销，且逐迭代累积。
- **关键观察**：注意力计算期间 CPU 和 RDMA NIC 处于空闲状态（InfiniGen 的预取技术中 KV 选择需先于注意力层完成）。
- **实现**：每层注意力开始时，解码节点通过 RDMA SEND 通知预填充节点"网络空闲"，预填充节点按重要性顺序（公式 1）用 RDMA WRITE 推送剩余 KV 块，并更新 mask。
- **干扰控制**：显式限制每次发送的 KV 块数——**推测比例（speculative ratio）设为 10%**，使全部剩余 KV 在约 10 次解码迭代内传完，且几乎不干扰按需传输。

### 与现有 KV 选择算法的兼容性
- SmartGen 通过统一的 **KV index 抽象**（形状 BH×k 的索引矩阵）与 InfiniGen、HATA 等算法兼容。
- 权重相关元数据在解码节点预加载，key-cache 相关元数据随预填充阶段传输（如 InfiniGen 部分比例 0.3 时增加 15% 传输量，由分析模型统一优化）。
