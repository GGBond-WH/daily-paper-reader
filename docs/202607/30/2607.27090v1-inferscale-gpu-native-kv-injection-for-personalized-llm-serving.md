## 摘要
大型语言模型越来越多地部署了持久化的个性化上下文，例如积累的记忆档案或长对话历史，这些上下文在用户的多次请求中共享。生产级内存系统（如Mem0、MemGPT和Zep）检索其中的相关子集并注入到提示中，迫使服务引擎重复预填充相同的内容。随着检索预算的增长，即便底层内存在请求间被重用，首令牌时间（TTFT）也会增加。我们提出了InferScale，一个GPU原生的LLM内存系统，用可重用的KV状态替代重复的提示预填充。InferScale预先计算每个记忆事实的KV表示，将其与语义嵌入一起存储在GPU上，在服务时检索相关事实，并将其KV直接注入到vLLM的分页缓存中。为了支持在旋转位置编码下动态组装记忆，我们引入了Chunked RoPE，它在旋转前存储键，并在注入时应用它们的服务时位置。然而，独立编码记忆事实会忽略联合预填充时可用的跨事实上下文。我们通过上下文窗口编码来缓解这个问题，该方法将每个记忆事实与前面对话上下文的一个小窗口一起编码，同时仅缓存目标事实的KV。InferScale通过vLLM的KV连接器接口实现，既不需要修改引擎，也不需要微调模型。在LoCoMo上的三个开放权重模型上，InferScale在检索预算增加时保持TTFT几乎恒定：在k=50时，它将TTFT降低了72-79%（3.6-4.8倍），实现了60.3%的准确率（而无需服务时重新计算的Mem0为63.3%），并在并发负载下提供了3.7-4.5倍的吞吐量。因此，可重用的KV状态将内存条件下的服务延迟与检索上下文大小解耦，同时保持应用质量。

## Abstract
Large language models are increasingly deployed with persistent personalized context, such as accumulated memory profiles or long conversation histories, that is shared across a user's many requests. Production memory systems (e.g., Mem0, MemGPT, and Zep) retrieve a relevant subset of this memory and inject it into the prompt, forcing the serving engine to repeatedly prefill the same content. As the retrieval budget grows, time-to-first-token (TTFT) increases even though the underlying memory is reused across requests.   We present InferScale, a GPU-native LLM memory system that replaces repeated prompt prefilling with reusable KV state. InferScale precomputes each memory fact's KV representation, stores it alongside a semantic embedding on the GPU, retrieves relevant facts at serving time, and injects their KV directly into vLLM's paged cache. To support dynamically assembled memories under rotary position embeddings, we introduce Chunked RoPE, which stores keys before rotation and applies their serving-time positions during injection. However, encoding memory facts independently omits the cross-fact context available during joint prefilling. We mitigate this with Context-Window Encoding, which encodes each memory fact together with a small window of preceding conversation context while caching only the target fact's KV.   InferScale is implemented through vLLM's KV-connector interface, requiring neither engine modifications nor model fine-tuning. Across three open-weight models on LoCoMo, InferScale keeps TTFT nearly constant as the retrieval budget increases: at k=50 it reduces TTFT by 72-79% (3.6-4.8x), achieves 60.3% accuracy versus 63.3% for Mem0 without serving-time recomputation, and delivers 3.7-4.5x the throughput under concurrent load. Reusable KV state thus decouples memory-conditioned serving latency from retrieved-context size while preserving application quality.

## 1. 核心问题与整体含义（研究动机和背景）
- **问题**：现有生产级LLM内存系统（如Mem0、MemGPT、Zep）在每次用户请求时，都将检索到的记忆事实以文本形式注入提示（prompt injection），导致服务引擎必须重复预填充这些相同的记忆内容。随着检索预算（top‑k）增加，首令牌时间（TTFT）线性增长，即使底层记忆内容在多次请求间完全重复。
- **意义**：传统KV缓存复用技术（如前缀缓存）假设复用内容处于固定位置，但个性化记忆系统每次动态组装不同子集，位置不定，无法有效复用。因此需要一种新机制，将记忆注入从“令牌层”转移到“注意力层”，消除重复预填充的二次开销。

## 2. 方法论：核心思想、关键技术细节
### 2.1 核心思想
- **KV注入**：将检索到的记忆事实的预计算键-值（KV）表示直接注入到GPU上的注意力缓存中，而无需重新预填充这些令牌。该注入在查询位置上与提示注入完全等价（定理3）。
- **离线/在线分离**：离线阶段一次性编码每个记忆事实的KV（存储在GPU）；在线阶段仅检索相关事实的KV并注入，只预填充查询令牌。

### 2.2 关键技术
- **Chunked RoPE**：解决位置编码问题。存储键时绕过旋转位置编码（RoPE），保留投影后的原始键（\(k_{\text{pre}} = W_K h\)）；在注入时根据当前提示位置动态旋转键。定理6证明该操作产生的注意力分数与在该位置直接预填充完全相同，实现位置无关的KV复用。
- **Context‑Window Encoding**：弥补独立编码丢失的跨事实上下文。在编码每个事实时，附加该事实前 \(w\) 个对话轮次构成上下文窗口，进行一次完整前向传播，但仅缓存目标事实的KV。保证存储的KV包含了窗口内上下文信息，而注入时不需携带这些额外令牌，属于纯离线成本。
- **系统实现**：集成到vLLM的KV‑connector接口，不修改引擎、不微调模型。GPU上同时维护Jasper（近似最近邻索引）和预RoPE KV存储，检索和注入均在同一设备完成。

## 3. 实验设计：数据集、基准、对比方法
- **数据集**：LoCoMo长对话问答基准的子集，包含10个对话、1540个可回答的QA对（涵盖单跳、多跳、开放域、时间推理四类）。
- **基准方法**：Mem0（默认生产配置：Qdrant CPU向量存储 + 提示注入）。
- **对比方法**：InferScale（GPU原生检索 + KV注入）与Mem0对比。附加消融：不同编码窗口 \(w \in \{0,5,20,50\}\)、不同检索预算 \(k \in \{5,10,20,50\}\)、GPU vs CPU KV存储。
- **评估指标**：准确率（Gemma-2-9B评判）、vLLM引擎TTFT、端到端查询到首令牌延迟、并发吞吐量（QPS）。

## 4. 资源与算力
- **硬件**：单张NVIDIA RTX PRO 6000 Blackwell Server Edition（96GB GDDR7，PCIe 5.0×16）。
- **软件**：vLLM v0.19.1，模型推理使用bfloat16。
- **训练**：无需模型微调或重训练。离线预处理时间（表4）：以Llama-3.1-8B为例，\(w=0\)时约39秒/对话，\(w=50\)时约206秒/对话（一次性成本）。
- **存储**：每个对话的KV存储占用1.8～4.8 GB GPU内存（取决于模型架构），Jasper索引和ID映射共约25 MB。

## 5. 实验数量与充分性
- **实验组**：共7组核心实验（延迟曲线、准确率表、吞吐量、向量后端消融、大模型验证、CPU offloading、经验等价性），每组覆盖多模型、多\(k\)、多\(w\)。
- **充分性**：
  - 覆盖3个主流7-8B模型（Llama-3.1-8B、Mistral-7B、Qwen2.5-7B）及14B模型（Qwen3-14B）。
  - 消融了编码窗口、检索预算、GPU/CPU存储、前缀缓存开关。
  - 基准Mem0采用其最佳配置（启用vLLM前缀缓存、Qdrant CPU存储）。

- **客观性**：实验设置公平，所有系统使用相同事实提取和检索管道，仅注入方式不同；报告了标准偏差（表20注）。

## 6. 主要结论与发现
- **延迟**：InferScale的TTFT几乎不随\(k\)增长（16-18 ms附近），而Mem0的TTFT随\(k\)线性增长（Llama-3.1-8B在\(k=50\)时为68 ms）。端到端查询到首令牌延迟，InferScale比Mem0快3.6-4.8倍。
- **准确率**：\(w=0\)（无上下文）时准确率随\(k\)下降（从62%降至54%）。使用\(w \geq 20\)后准确率恢复，在\(k=50\)时达到60.3%（Mem0为63.3%），多跳问题差距较大（约6-16个百分点），单跳和开放域接近或反超。
- **吞吐量**：并发100用户时，InferScale达100+ QPS，Mem0仅27 QPS，吞吐量提升3.7-4.5倍，近线性扩展。
- **CPU offloading**：将KV存储放在主机DRAM并实时流式传输至GPU，TTFT仅增加1.5-3 ms，端到端延迟增加约33-38 ms，但仍比Mem0快2.3倍。
- **经验等价性**：在18个测试案例中，9个输出完全相同，8个语义等价，仅1个不同但事实准确率100%。证实KV注入与提示注入在实用中几乎等价。

## 7. 优点
- **创新性**：首次提出将检索记忆直接以KV形式注入注意力缓存，理论上严格等价，实践上显著加速。
- **位置独立性**：Chunked RoPE使得任意位置注入精确成立，不依赖前缀缓存命中。
- **轻量部署**：无需修改LLM引擎、无需微调、兼容现有检索管道。
- **实验全面**：涵盖多模型、多预算、多窗口、CPU offloading、经验等价性，验证了鲁棒性。
- **实用性强**：单GPU即可部署，CPU offloading方案在牺牲少量延迟下解除GPU内存瓶颈。

## 8. 不足与局限
- **GPU内存瓶颈**：每个对话的KV存储占用数GB，限制了单GPU同时服务的用户数（Llama下约10个对话）。
- **准确率未完全追上提示注入**：在多跳推理任务上仍有明显差距（最大16个点），说明独立编码丢失的跨事实注意力难以完全由窗口补偿。
- **数据集单一**：仅使用LoCoMo数据集，未验证在其他RAG或长文档场景的泛化性。
- **不支持在线更新**：当前KV存储为离线一次性构建，无法增量添加、修改或删除记忆事实。
- **单节点局限**：未探索多GPU或多节点部署，因此扩展性受限于单GPU内存和带宽。
- **未深入分析数值误差**：虽通过经验等价性验证了实际输出接近，但未系统分析bf16非确定性对长序列累积误差的影响。
